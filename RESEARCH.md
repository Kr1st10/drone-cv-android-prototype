## 1. Источники

### 1.1 sapoepsilon/yolov11s-drone-detector (Hugging Face)
https://huggingface.co/sapoepsilon/yolov11s-drone-detector · ревизия `58897d6d6fadda9dfec979fd5dd7ad9040e73365`
- **Опубликовано:** `best.pt` (19 160 211 байт, SHA-256 `337390e1…0aa01b78`), `results.csv`, model card.
- **Веса:** есть, только PyTorch (`.pt`, FP16). ONNX/TFLite не опубликованы.
- **Технологии:** Ultralytics YOLO11s, fine-tune с `yolo11s.pt`, imgsz 640, 1 класс `drone`.
  Данные: `pathikg/drone-detection-dataset` (~54k изображений, MIT).
- **Заявлено автором (не проверено нами):** на Anti-UAV-RGBT P 0.929, R 0.759, AP@0.5 0.741;
  последняя эпоха `results.csv`: mAP50 0.946, mAP50-95 0.605 (валидация на своих данных).
- **Польза:** готовый специализированный детектор нужного класса, небольшой размер.
- **Ограничения (по карточке):** один класс; recall падает на малых/далёких дронах (~76%).
- **Лицензия:** карточка — Apache-2.0. **Но** базовая модель и экспортёр Ultralytics — AGPL-3.0,
  экспортированный ONNX содержит метаданные `license: AGPL-3.0`. Право автора на перелицензирование
  производной модели не подтверждено → **считаем веса AGPL-3.0** до юридической проверки.
- **Проверено нами:** см. §3 (экспорт в ONNX, тензоры, инференс, базовая оценка).

### 1.2 eahmeddarwish/drone-detection-yolov5 (GitHub)
https://github.com/eahmeddarwish/drone-detection-yolov5
- **Опубликовано:** Python-скрипты (детекция на фото/видео, трекер Kalman+PID для pan/tilt на Raspberry Pi 4).
- **Веса:** `models/best.onnx`, `best2.onnx`, `best.pt` — через Git LFS (в дереве лежат LFS-указатели ~133 байта).
  Нами не скачивались и не проверялись.
- **Технологии:** YOLOv5s → ONNX, ONNX Runtime на CPU, Kalman, PID, PCA9685.
- **Заявлено автором:** mAP@0.5 99%, ~1% FP, 15–20 FPS на Pi 4 — на собственной валидации, не проверено.
- **Польза:** подтверждает путь YOLO → ONNX → ONNX Runtime на CPU; полезный урок —
  без фоновых (негативных) изображений модель даёт массовые ложные срабатывания.
- **Лицензия:** код MIT (файл LICENSE подтверждён); веса — производные от YOLOv5 (AGPL-3.0), как пишет сам автор.
- **Не проверено:** классы и формат выхода ONNX, качество на наших данных.

## 2. Выбор модели

| Критерий | YOLO11s drone (HF) | YOLOv5s drone (Darwish) | yolov8.onnx (Kukharev) |
|---|---|---|---|
| Класс `drone` | да, 1 класс (метаданные ONNX `{0: 'drone'}`) | заявлено | неизвестно |
| Веса доступны | да, закреплённая ревизия HF | да, Git LFS | файл есть, происхождение неизвестно |
| Android | ONNX-экспорт проверен нами, ORT Android | ONNX, не проверено | не проверено |
| Выходной тензор | `[1,5,8400]`, проверен | не проверен | не проверен |
| Размер | 19 МБ `.pt` / 36 МБ ONNX FP32 | — | 12 МБ |
| Лицензия | Apache-2.0 (карточка) / AGPL-3.0 (база) | MIT код / AGPL-3.0 база | нет лицензии |

**Выбор: `sapoepsilon/yolov11s-drone-detector`**, конвертированная в ONNX, инференс через
**ONNX Runtime Android** (MIT). Причины: нужный класс, закреплённые веса с SHA-256, документированный
формат, современная архитектура, наш экспорт и проверка выходного тензора прошли, приемлемый размер.
LiteRT/TFLite отложен: конверсия Ultralytics → TFLite требует TensorFlow/onnx2tf (тяжело и хрупко),
ONNX Runtime использует тот же файл, что и Python-проверка.

## 3. Наши проверки модели (sandbox, CPU)
- Экспорт: `ultralytics==8.3.120`, `torch==2.6.0+cpu`, `onnx==1.17.0`, `onnxslim==0.1.48`, opset 17, 640×640, без NMS.
- Два независимых экспорта дают одинаковый граф; различалось только поле метаданных `date` →
  скрипт его удаляет, итоговый SHA-256 воспроизводим: `a566be56e08e8cdffebc573c6d4bb1a5fa0c864589ef97f58d5b7325e6451c19`.
- Вход `images` float32 `[1,3,640,640]` (RGB, 0..1, NCHW); выход `output0` float32 `[1,5,8400]`:
  `cx, cy, w, h` в пикселях входа 640 + score класса `drone` (уже после sigmoid). NMS в модели нет.
- Базовая оценка — см. `PROJECT_STATE.md` (числа только с указанием набора и порогов).
