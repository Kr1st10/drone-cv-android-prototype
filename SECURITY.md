# Безопасность и сообщение о проблемах

Сведения для разработчиков и пользователей тестового Android-приложения. Они относятся к текущей разработке `0.5.2`; подтверждённой программы поддержки релизов и SLA исправлений нет.

## Данные и доступ

Приложение запрашивает CAMERA для живой камеры, использует системный Photo Picker для выбранного изображения и CreateDocument для явного экспорта JSON. В manifest нет INTERNET, `allowBackup=false`; инференс локальный. Работа системного/облачного провайдера файлов регулируется самим провайдером. Подробные границы и данные экспорта — [интеграции](docs/reference/integrations.md).

Фото/результаты и последний отчёт удерживаются в памяти; история в БД и загрузка кадров на сервер не реализованы. Экспорт содержит сведения об устройстве, времени, ресурсах и настройках, а также координаты и confidence выбранного обнаружения, номера сигнала и активации analyzer; просмотрите его перед распространением. Журналы могут содержать URI, пути и тексты ошибок. Для тестов используйте разрешённые изображения без личных данных и согласованное тестовое устройство.

ONNX устанавливается с проверкой SHA-256; это не подтверждение безопасности содержимого или урегулирования лицензии весов. Происхождение и конфликт лицензий зафиксированы в [MODEL](ml/MODEL.md). Не отключайте проверку и не добавляйте произвольную модель в опубликованный APK без проверки.

## Сообщение об уязвимости

Приватный канал приёма сообщений и ответственный за него в репозитории не определены. Не публикуйте токены, персональные данные, приватные файлы и подробности эксплуатации в открытом issue/PR. Если репозиторий предоставляет включённую GitHub Private Vulnerability Reporting, используйте её; доступность этой функции здесь не подтверждена. Иначе сначала согласуйте приватный способ связи с сопровождающим через уже известный вам контакт. Адрес, которого нет в источниках, не придумывается.

Для приватного разбора подготовьте Git SHA/APK-источник, затронутый компонент, условия и минимальное воспроизведение на обезличенных данных, возможные последствия и безопасные логи. Не проверяйте проблему разрушительными действиями на чужих данных. Получение сообщения/срок ответа до назначения канала не гарантируются. Отсутствующий безопасный канал отмечен как `BLOCKED` в [аудите стандарта](docs/documentation-audit.md).

## Секреты и проверка изменений

Не коммитьте API-ключи, токены, keystore, пароли подписи, local.properties и приватную production-конфигурацию. Обычному локальному инференсу API-ключ не нужен. Production signing/secrets-процесс не настроен; debug-сборка не служит его описанием.

Перед PR проверьте diff и новые файлы, ограничения доступа и экспорта, отсутствие секретов/личных данных. Автоматическая полноценная secret-scanning проверка в workflow проекта не описана; локальная эвристика не доказывает отсутствие всех секретов. Порядок проверок — [CONTRIBUTING](CONTRIBUTING.md), диагностика сбоев — [runbook](docs/operations/runbook.md).
