# Этап 4.3 — AOD 4: воспроизведение

Внешний источник, **не гарантированно независимый** от обучения модели: [AOD 4](https://data.mendeley.com/datasets/cd5z895tr2/1), Vama Soni, Dhruval Shah, Jeel Joshi, 2024, DOI 10.17632/cd5z895tr2.1, CC BY 4.0. [Статья](https://pmc.ncbi.nlm.nih.gov/articles/PMC11372627/) указывает Anti-UAV, YouTube-8M и Roboflow; сами первичные видео могут иметь дополнительные права. Автор весов сообщал об оценке на Anti-UAV, так что это не полностью ранее не виденный тест. Фактический train/val модели не опубликован. Использованы все три split AOD4, **не только test AOD4**: ни один не применялся нами для обучения/подбора порогов, но это не официальный AOD test benchmark.

160 изображений 1024×1024: 80 содержат рамки drone (3 кадра с минимальным размером <16, 6 — 16–24, 2 — 24–30, 69 — ≥30 px), 30 отобраны по bird, 30 по airplane и 20 без аннотаций. Группы заданы для изображений; размеры объектов и их количество вычисляются отдельно. Размер — √(w×h) в пикселях AOD4 после исходного ресайза до 1024, без округления. Отбор не отражает частоты реальных сцен. Неразмеченные дроны на отрицательных кадрах и ошибки первичной разметки возможны. Некоторые рамки <16 px при просмотре сомнительны: подвыборку нельзя считать надёжной проверкой сверхмалых дронов.

## Отбор и ограничения

`independent_prepare.py`: для трёх split по порядку редкости <16, 16–24, 24–30, ≥30 px до 80 положительных, затем 30 bird, 30 airplane и 20 empty. Внутри каждой группы порядок по SHA-256 строки `stage4.3-seed0:<split>:<filename>`, без использования предсказаний модели. Не более одного изображения на распознанную последовательность глобально; одинаковый видео-ID YouTube, Anti-UAV или V_* считается одной последовательностью. Для имён неизвестного формата применяется исходная часть имени, что не гарантирует разных видео. Дополнительно исключаются пары, одновременно имеющие dHash расстояние ≤4 и среднюю разницу 32×32 RGB <5/255; это эвристика, возможны пропущенные дубликаты и исключение независимых похожих сцен. Поскольку группы отобраны приоритетно, редкие последовательности могут не дать более крупные объекты. Манифесты содержат split, ID, имя, выведенный sequence ID, рамки и SHA-256 каждого изображения. Изображения не публикуются.

Источники-кандидаты: [Anti-UAV](https://github.com/zsx060/Anti-UAV-datasets) — RGB только в 300, 410/600 IR; MIT указан для проекта, права на данные необходимо проверять отдельно. [YOLOBirDrone](https://www.csio.res.in/CommonNew.php?ds=401&page=1) доступен для исследования, но его полная версия предоставляется по запросу и запрещена публичная перепубликация; пробный набор содержит только 10 кадров. Он не использован в метриках.

## Команды

В Linux из корня проекта: зависимости `ml/requirements.txt` и CPU torch в версиях этапа 4.2; экспорт 640/960 из того же проверенного `best.pt` по `ml/results/resolution/README.md`. Большие веса и данные не коммитятся. Архив AOD4: 1 921 835 727 байт, SHA-256 `fac56b9c0494312bcd4c63dfefcbcd8ed07ab55d4b00584131c0b55273d24518`. Официальный архив имеет ZIP-замечание от `unzip`, Python `zipfile` читает выборочные файлы; скрипт проверяет хеш и читаемые данные.

```bash
export OPENBLAS_NUM_THREADS=1
python ml/scripts/independent_prepare.py --download
# при уже скачанном архиве: python ml/scripts/independent_prepare.py --archive /path/to/AOD4.zip
python ml/scripts/independent_overlap.py --train  # дополнительно скачивает 9 train и test shard pathikg, ~4.4 GB; train удаляются после анализа
for mode in 640 960 sahi416; do python ml/scripts/independent_experiment.py run --mode "$mode"; done
python ml/scripts/independent_experiment.py report
python ml/scripts/render_independent_examples.py
python -m pytest ml/tests -q
```

Одинаковые кадры и веса, conf >0.5, NMS IoU 0.7, однозначный greedy match IoU ≥0.5; SAHI 416, overlap 0.2, full frame, GREEDYNMM/IOS 0.5. FP на negative — все детекции в кадрах без аннотаций drone. Число FP **на изображениях** bird/airplane не означает, что рамка обязательно попала на птицу/самолёт; отдельно вычисляется число FP с IoU ≥0.5 с их рамкой (атрибуции могут перекрываться). JPEG decode исключён из измеренного времени; каждый режим — новый процесс, 3 прогрева. `raw_*.json` и визуальные изображения хранятся локально и игнорируются; `records_*.json` и `metadata_*.json` содержат детекции по кадрам, на их основе report можно пересчитать без повторного инференса; `examples.json` сохраняет адреса, разметку и результаты, чтобы локально отрисовать характерные случаи. `summary.json` — агрегаты. Доля нераспознанных исходных последовательностей и неопубликованный состав обучения не дают доказать независимость.
