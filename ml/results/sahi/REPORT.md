# Этап 4.1 — SAHI для малых дронов: отчёт

_2026-11-02. Только Python-исследование; Android, CameraX и модель не менялись._
Полные таблицы — [`REPORT_TABLES.md`](REPORT_TABLES.md) (генерируются из `sahi_eval.json`), агрегаты — [`summary.json`](summary.json),
примеры — [`examples.json`](examples.json).

## 1. Что сравнивалось

- **Модель:** прежняя YOLO11s `sapoepsilon/yolov11s-drone-detector` @ `58897d6d…`, `best.pt` SHA-256
  `337390e1…0aa01b78` → ONNX 640×640 FP32, SHA-256 `b4867481a3b3277f7b17e69b7b45077567d6929157e72dd5d48542dd34f19eb7`
  (экспорт `fetch_and_export.py` повторён в этой среде, хеш совпал). Новой модели/дообучения нет.
- **Baseline:** один full-frame инференс, эталонный пайплайн `drone_detector.py` (letterbox 640 → ORT → NMS IoU 0.7),
  тот же, что повторяет Android.
- **SAHI:** официальный `obss/sahi` 0.14.0 `get_sliced_prediction` (нарезка, сдвиг координат в полный кадр, слияние)
  вокруг того же пайплайна (адаптер `DroneSahiModel` в `sahi_experiment.py`). Каждый слайс letterbox-ится в 640,
  т.е. слайс 320 увеличивается ×2, 416 — ×1.54. Внутри инференса NMS IoU 0.7; между слайсами GREEDYNMM,
  class-agnostic, порог 0.5.

| Режим | Слайс / overlap | Full-frame проход | Метрика слияния |
|---|---|---|---|
| `sahi_320_ov0.2_full` | 320 / 0.2 (640×480 → 6 слайсов) | да | IOS |
| `sahi_320_ov0.2_tiles` | 320 / 0.2 | нет | IOS |
| `sahi_416_ov0.2_full` | 416 / 0.2 (640×480 → 4 слайса) | да | IOS |
| `sahi_416_ov0.2_full_iou` | 416 / 0.2 | да | IOU (абляция, добавлена после 1-го прогона) |

Обоснование: overlap 0.2 и GREEDYNMM/IOS 0.5 — значения SAHI по умолчанию; IOS сливает обрезанный фрагмент
с полной рамкой соседнего слайса. Full-frame проход нужен для крупных дронов, которые слайс разрезает.
`conf` 0.25 — как в прежней оценке (`SUMMARY.md`), 0.5 — порог Android по умолчанию.
TP — IoU ≥ 0.5 с ещё не сопоставленной GT, жадно по score (`evaluate.match`), т.е. второй бокс на один объект — FP.

## 2. Выборка (`subset.json`, `select --seed 0`)

- **Позитивы: 360 изображений / 383 GT** из test-сплита `pathikg/drone-detection-dataset` @ `004b46cc` (кадры 640×480
  из YouTube-видео, разметка MIT). Стратификация по наименьшей GT в кадре (√площади): 120 «<16 px», 120 «16–32 px»,
  60 «32–96 px», 60 «≥96 px»; случайно внутри страты. Итог по GT: <16 px — 118, 16–24 px — 72, 24–32 px — 51,
  32–96 px — 82, ≥96 px — 60.
- **Негативы: 200 изображений COCO val2017** (`prepare_eval_data.py`, seed 0): 100 «hard» с bird/airplane/kite,
  100 случайных; класса drone в COCO нет — отсутствие дронов предполагается.
- **Не независимо:** автор модели обучался на «~54k» = train+test этого датасета. Исключены 30 известных
  near-duplicates из `split_overlap.json` (из 78 найденных ранее; остальные 48 id не сохранены и могли попасть в выборку).
  Числа — сравнение режимов на одних данных, не оценка качества в поле. Сложные фоны есть только в COCO hard и в
  части кадров pathikg (облака, деревья, здания); собственных снимков нет.

## 4. Наблюдения

1. **Recall растёт, но умеренно:** лучший режим `sahi_416_full` при conf 0.5 — R 0.755 → 0.812 (+22 GT нетто из 383),
   P на позитивах сохраняется (0.929 → 0.934). Для <16 px +0.042, для 16–24 px (≈ «20 px») +0.014 (1 GT) —
   у самых «целевых» ~20 px эффект почти нулевой. Медиана размера найденных дополнительно GT ≈ 30 px; часть
   «прироста» — лучшая локализация (IoU ≥ 0.5), а не новые обнаружения.
2. **Ложные срабатывания на сценах без дронов растут сильно** — прежняя главная слабость модели:
   hard 37 → 60, random 17 → 37 изображений из 100 при conf 0.5 (320: 68 / 49). Увеличенные слайсы дают
   уверенные (0.7–0.9) рамки на людях вдали, воздушных змеях, птицах. P/R на позитивах этого не показывают.
3. **Слияние — источник ошибок.** IOS «проглатывает» маленькую верную рамку большой ложной рамкой из слайса,
   которая её содержит (≈ половина потерянных GT; пример `lost` в `examples.json`). Абляция IOU устраняет потери
   (−0), но не сливает фрагменты: 40–61 FP-дублей на найденных GT, P 0.835. Unit-тест также фиксирует, что
   GREEDYNMM нетранзитивен: при равных score тонкий фрагмент на границе слайса может остаться вторым боксом.
4. **Без full-frame прохода (tiles only)** хуже baseline: крупные дроны режутся (recall ≥96 px 0.917 → 0.733).
5. **Цена:** ×4.9–7.1 времени CPU на кадр 640×480; при 416 — 5 инференсов вместо одного.

## 5. Вывод для Android

**Не внедрять SAHI в живой режим сейчас.** Выигрыш recall (+5.7 п.п. на не независимых данных, почти 0 для ~20 px)
не оправдывает ~5× вычислений на кадр и почти двукратный рост кадров-негативов с ложной тревогой. Кадры pathikg —
640×480, как вход анализа CameraX, поэтому SAHI здесь — это фактически апскейл; на кадрах высокого разрешения
эффект может отличаться (не проверено).

## 6. Ограничения

- Позитивы из того же датасета, что обучение (не независимы; 48 из 78 near-duplicates не исключены); 360 кадров,
  ~50–120 GT на корзину — доверительные интервалы широкие (±5–9 п.п. на корзину).
- Негативы COCO не гарантированно без дронов; FP просмотрены выборочно (`examples.json`).
- Нет собственных снимков камеры телефона, нет видеопоследовательностей/трекинга, нет высокого разрешения.
- Время — Python на sandbox CPU, не Android; батчинг слайсов не использовался.
- Порог/параметры не подбирались по сетке (сознательно немного конфигураций); IOS/IOU 0.5 не варьировались.

## 7. Следующие эксперименты

1. Собственный независимый набор с телефона (малые дроны 10–30 px, небо/деревья/птицы) — без него решение не окончательно.
2. Дешёвые альтернативы: один инференс с бо́льшим входом той же модели (повторный экспорт тех же весов 960/1280),
   SAHI только по ROI (небо / окрестность прежней детекции) или «глубокий скан» по запросу в фото-режиме.
3. Подавление FP: более высокий порог только для детекций из слайсов, фильтр по размеру/форме, дообучение на
   фоновых изображениях (отдельный этап).
4. Слияние: IOS с ограничением отношения площадей (не сливать маленькую рамку в большую) — устранить «проглатывание».

## 8. Воспроизведение

```bash
# окружение и данные — как в ml/README.md (torch 2.6.0 CPU, pip install -r ml/requirements.txt, включая sahi==0.14.0)
python ml/scripts/fetch_and_export.py && python ml/scripts/prepare_eval_data.py
python ml/scripts/sahi_experiment.py select        # должен воспроизвести subset.json
python ml/scripts/sahi_experiment.py run           # ~45 мин на 2 vCPU -> sahi_eval.json (git-ignored, ~0.9 МБ)
python ml/scripts/sahi_experiment.py report        # REPORT_TABLES.md, summary.json
python ml/scripts/sahi_examples.py --mode sahi_416_ov0.2_full --conf 0.5 --render   # examples.json (+ картинки, git-ignored)
python -m pytest ml/tests -q                       # 16 тестов
```
