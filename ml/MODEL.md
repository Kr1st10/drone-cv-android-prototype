| Точность | FP32 (`half=False`) |

Поле метаданных `date` удаляется скриптом. SHA-256 ONNX зависит от версий torch/ultralytics/onnxslim:
предыдущий агент при `ultralytics 8.3.120` получил другой хеш (`a566be56…`) — это ожидаемо. Проверять
корректность нужно по паритету выходов (§5), а не по побайтовому совпадению.

## 3. Тензоры

**Вход** `images`: `float32 [1, 3, 640, 640]`, NCHW, порядок каналов **RGB**, значения `pixel / 255` в `[0, 1]`,
без mean/std-нормализации.

**Выход** `output0`: `float32 [1, 5, 8400]` (каналы × якоря; транспонировать в `[8400, 5]`).
- `[0..3]` = `cx, cy, w, h` — центр и размер рамки **в пикселях входа 640×640** (после letterbox);
- `[4]` = score класса `drone` в `[0, 1]` (sigmoid уже применён в графе; objectness отдельно нет);
- 8400 = 80² + 40² + 20² ячеек (страйды 8/16/32).

## 4. Предобработка и постобработка (эталон — `ml/scripts/drone_detector.py`)

1. **Letterbox** (как `ultralytics.data.augment.LetterBox`, квадрат 640):
   `r = min(640/H, 640/W)`; `newW = round(W·r)`, `newH = round(H·r)`; resize билинейно;
   `dw = (640-newW)/2`, `dh = (640-newH)/2`; паддинг `left = round(dw-0.1)`, `top = round(dh-0.1)`
   (правая/нижняя — остаток), цвет `(114,114,114)`.
   Пример: 640×480 → `r=1`, `top=80`; 1920×1080 (портрет 1080×1920) → `r=1/3`, `left=140`.
2. RGB uint8 → float32 `/255`, HWC → CHW.
3. Декодирование: для каждого из 8400 столбцов `score = out[4]`; оставить `score > conf`.
4. `x1 = cx − w/2`, `y1 = cy − h/2`, `x2 = cx + w/2`, `y2 = cy + h/2`.
5. NMS (жадный, IoU > `iou` подавляется, сортировка по убыванию score), `max_det = 300`.
   Класс один → class-agnostic NMS эквивалентен поклассовому.
6. Обратное преобразование: `x = (x − left) / r`, `y = (y − top) / r`, обрезка к `[0, W] × [0, H]`.
7. Пустой результат — штатная ситуация: возвращается пустой список (покрыто тестами).

Пороги по умолчанию — как у Ultralytics: `conf = 0.25`, `iou = 0.7`. Для приложения порог нужно выбирать
по таблице в `ml/results/SUMMARY.md` (компромисс recall ↔ ложные срабатывания).

Для Android: в `ImageProxy` учитывать `rotationDegrees` до letterbox; координаты рамок переводить в систему
координат превью отдельно (это следующий этап).

## 5. Проверенные свойства и ограничения

Подробные числа — `ml/results/SUMMARY.md`. Кратко:
- ONNX Runtime и PyTorch FP32 на одинаковом входе совпадают (макс. |Δ| координат ≈ 4·10⁻³ px, score ≈ 2·10⁻⁵).
- Наш пайплайн на ONNX совпадает с `YOLO("best.pt").predict` (304/304 рамок, |Δ| < 10⁻³ px).
- **Тестовый набор не независим** (см. §6). Метрики на нём — верхняя оценка, не качество в поле.
- **Много ложных срабатываний вне домена**: на изображениях COCO без дронов модель часто выдаёт рамки
  (самолёты, птицы, а также крупные рамки на «пустых» сценах — еда, люди, животные). Вероятная причина —
  в обучающем наборе нет фоновых изображений (в test-сплите 0 изображений без дрона).
  Отсутствие ложных срабатываний не гарантируется ни при каком пороге.
- Recall падает на малых объектах (<32 px по √площади ≈ 0.81 против 0.97 для ≥96 px).
- Разметка pathikg частично автоматическая (по карточке датасета) — встречаются пропущенные рамки,
  что занижает precision.

## 6. Независимость тестового набора

- Набор: `pathikg/drone-detection-dataset` (MIT), ревизия `004b46cc…`, split `test`, 2625 изображений 640×480,
  2863 рамки; все кадры — из YouTube-видео (по карточке), имена файлов `VS_P*.jpg`.
- Автор модели пишет «trained from pathikg (~54k images)»; train + test = 51 446 + 2 625 = 54 071 ≈ 54k.
  Какой split использовался для обучения и валидации, автор не публикует (`train_args.data` указывает на
  локальный `dataset.yaml`). **Высока вероятность, что test-сплит видела модель** (обучение или валидация).
- Наша проверка `ml/scripts/check_split_overlap.py` (train ↔ test публичного датасета): совпадающих имён
  и побайтовых дубликатов нет, но 78 из 2625 test-кадров (3.0 %) — почти дубликаты train-кадров
  (dHash, расстояние Хэмминга ≤ 4), т.е. кадры из тех же видео.
- Вывод: test-сплит **не является независимым** тестом. Для честной оценки нужен собственный набор,
  снятый нашей камерой, или внешний набор с проверенным происхождением.
