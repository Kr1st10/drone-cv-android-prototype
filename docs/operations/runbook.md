# Диагностика и восстановление приложения

Практическая инструкция для разработчика/тестировщика Android-приложения. Серверной эксплуатации, дежурной смены и SLA в проекте нет; приведены действия на компьютере сборки и своём тестовом телефоне.

## Собрать сведения до действий

Зафиксируйте Git SHA/APK-источник, версию приложения, телефон, Android/API, выбранные zoom/physical ID/потоки/порог, фазу UI и точный текст ошибки. Команды из корня репозитория с настроенным PATH:

```bash
git rev-parse --short HEAD
java -version
./gradlew --version
adb devices
```

Для локальной сборки смотрите `app/build/reports/tests/testDebugUnitTest/` и `app/build/reports/lint-results-debug.*`. Для GitHub проверяйте конкретный run и его artifacts согласно [описанию CI](../development/testing.md#github-actions).

## Симптом → проверка → действие

| Симптом | Проверка и возможная причина | Восстановление и критерий успеха |
|---|---|---|
| Gradle не стартует / неверная Java | Сравните Java из `./gradlew --version` с JDK 17; shell и IDE могут выбирать разные JDK | Выберите JDK 17 в JAVA_HOME/Gradle JDK, повторите сборку; ожидается корректная версия и успешная задача |
| `SDK location not found` / нет platform | Проверьте `sdk.dir` либо ANDROID_HOME, наличие SDK 35/Build-Tools 34.0.0 и лицензий | Настройте SDK по [быстрому старту](../getting-started.md), повторите сборку |
| `Model missing` | ONNX отсутствует в assets либо JVM-пути; не входит в Git | Получите проверенный ONNX, выполните install_android_model.py; ожидается `[install] OK` и успешный verifyDroneModel |
| `Model SHA-256 mismatch` | Файл не соответствует `android.onnx_sha256`; возможен другой экспорт/повреждение | Повторно получите точный артефакт; не отключайте проверку. Успех — проверка install/Gradle/APK |
| Python APK verifier: нет `hashlib.file_digest` | Команда запущена Python ниже 3.11 | Используйте Python 3.11+; скрипт не требует ML-библиотек |
| Два parity tests skipped | Нет `ml/data/android_parity/reference.tsv`/связанных файлов | Для работы приложения не препятствие; для проверки parity подготовьте fixtures по make_android_reference.py, затем повторите тесты. Не называйте skip успешным сравнением |
| ADB `unauthorized` / нет цели | Проверьте USB-отладку, подтверждение на телефоне, вывод adb devices | Подтвердите доступ/подключите устройство; перед установкой цель должна быть `device` |
| Установка отклонена | Прочитайте причину Android: подпись, версия, ABI, доступное место | Используйте совместимую проверенную сборку. Удаление пакета стирает данные и не является штатным первым действием; см. [развёртывание](../deployment.md) |
| Нет разрешения камеры | Экран объяснения, отказ/постоянный отказ, отзыв в настройках | Выдайте CAMERA кнопкой или системными настройками; вернитесь в приложение, ожидайте превью |
| Камера занята | Recoverable CameraState: камера используется другим приложением | Освободите камеру, дождитесь переподключения; новые результаты должны появиться без старых рамок |
| Critical ошибка камеры | Код в UI/logcat, недоступная задняя камера/политика ОС/bind | Устраните причину, нажмите «Повторить»; отсутствие hardware не исправляется повтором |
| 5×/physical ID не работает | Zoom range, warning, current zoom/IDs и inventory JSON | Вернитесь к 1×/auto. Код пытается сделать это при отказе нестандартного binding; после recovery проверьте превью и свежую детекцию |
| Ошибка модели во время камеры | Live ERROR и `LiveDetection` log | Stop, затем Start. При повторе проверьте модель/память; успешный новый кадр должен перейти в RUNNING |
| Нет рамок | Различайте EMPTY, STOPPED/STARTING/ERROR и отсутствие свежего кадра; модель может ошибаться | Проверьте счётчик завершений/тайминги, реальный порог и сцену. Нельзя считать отсутствие рамок поломкой или подставлять фиктивную рамку |
| Рамки исчезают через паузу | Result expiry через 1500 мс при отсутствии новых результатов | Проверьте, поступают ли новые кадры/streaming; expiry не означает отдельную ошибку модели |
| Фото не открывается | ACCESS/IMAGE/MEMORY и `PhotoDetection` log | Выберите доступное корректное изображение; при ошибке памяти уменьшите исходник/перезапустите после сохранения отчёта. Проверьте READY и завершённый infer |
| JSON не сохраняется | Статус ошибки экспорта; доступность выбранного provider/файла | Повторите с доступным назначением и проверьте чтение JSON; отмена диалога не экспортирует файл |
| Диагностика помечена interrupted | reason; фон/поворот/порог/Stop/rebind/ошибка | Это явная остановка сессии, не пропажа данных молча. Экспортируйте, верните условия и начните новую сессию после прогрева |

После вмешательства повторите конкретный сценарий и его проверку, сохранив текст прежней ошибки. Бесконечный повтор при неизменных условиях не заменяет диагностику.

## Логи и измерения

Источники Android-логов: `PhotoDetection` — decode/infer/release фото; `LiveDetection` — infer/release камеры; `CameraPreview` — bind и его ошибки. Прочитать последние сообщения выбранного тестового устройства:

```bash
adb logcat -d -s PhotoDetection LiveDetection CameraPreview AndroidRuntime
```

Команда читает уже накопленный журнал и не очищает его. Перед публикацией удалите посторонние сообщения, URI, личные пути/данные. Android/OEM может ограничивать доступность журналов.

При медленной работе экспортируйте реальную сессию по [PERFORMANCE_QA](../PERFORMANCE_QA.md). Сопоставляйте pipeline, ORT, ресурсы и условия; pipeline не является capture-to-display latency, температура батареи не температура CPU. Для camera ID/zoom сохраняйте inventory после каждого выбранного режима по [CAMERA_QA](../CAMERA_QA.md). Отсутствие physical ID не доказывает отсутствие модуля.

## Границы восстановления и эскалация

Перезапуск процесса теряет фото/отчёт в памяти; сначала экспортируйте нужное. Не выполняйте `pm clear`, uninstall, удаление dataset/weights или смену хеша ради диагностики. Приватная проверенная копия модели восстанавливается из assets штатно; отдельной процедуры восстановления пользовательской БД нет, потому что БД отсутствует.

Дежурные, контакты поддержки и сроки реакции не установлены. Для обычного воспроизводимого дефекта подготовьте обезличенное описание и приложите его к PR/issue репозитория. Для возможной уязвимости используйте правила и ограничения [SECURITY](../../SECURITY.md); приватный канал пока не определён. Устройство без доступного сенсора, ошибки OEM и непроверенная процедура rollback требуют участия сопровождающего, а не выдуманной команды восстановления.
