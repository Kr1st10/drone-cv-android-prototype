# Сборка, установка и обновление APK

Инструкция для разработчика и сопровождающего тестовые Android-устройства. Подтверждённый процесс проекта выпускает debug APK; публикация подписанного production-релиза и испытанный автоматический откат не настроены.

## Цели и предпосылки

APK поддерживает API 26+ и ABI `arm64-v8a`/`x86_64`. Для камеры требуется задняя камера и runtime-разрешение CAMERA. Целевой телефон проекта и список аппаратных ограничений описаны в [README](../README.md), версии инструментов — в [конфигурации](reference/configuration.md).

Для локальной сборки подготовьте JDK/SDK и точный ONNX по [быстрому старту](getting-started.md). Для установки готового `app-debug` из Actions нужен ADB или ручная установка APK на собственное тестовое устройство; повторный экспорт модели не требуется. Проверьте происхождение артефакта, Git SHA, versionName/versionCode и наличие модели. Результаты CI относятся только к конкретному commit/run.

## Подготовить и установить debug-сборку

Из корня репозитория с подготовленным окружением:

```bash
./gradlew --no-daemon assembleDebug assembleDebugAndroidTest testDebugUnitTest lintDebug
python3 ml/scripts/verify_apk_model.py app/build/outputs/apk/debug/app-debug.apk
adb devices
```

До установки выберите одно тестовое устройство в состоянии `device`, сохраните неэкспортированный отчёт из работающего приложения и убедитесь, что установка разрешена владельцем устройства. Следующая команда обновляет пакет на выбранном устройстве:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n ru.university.dronecv/.MainActivity
```

Успех установки — `Success`, затем открываются вкладки и живое превью после разрешения камеры. Проверьте хотя бы один завершённый infer, штатный пустой результат, Stop и повторный запуск по [быстрому старту](getting-started.md#установить-и-проверить-интерфейс). Наличие рамки на случайной сцене не является health check. Внешнего endpoint readiness/health у мобильного приложения нет (`N/A`).

`./gradlew installDebug` — альтернативная локальная установка после сборки. Не выполняйте установку на несколько устройств без проверки целей. Команды установки/старта в текущем документационном задании на телефоне не запускались; локальная сборка проверена отдельно в [аудите](documentation-audit.md).

## Обновление, данные и откат

Обновление предполагает тот же applicationId и совместимую подпись/версию. Debug-keystore может различаться между компьютерами и CI. При отказе Android из-за подписи или versionCode сохраните ошибку и текущий APK/условия; не используйте удаление пакета как автоматический способ исправления. Оно удаляет приватные данные, а процессное состояние фото и отчёта не восстановится. Неэкспортированный отчёт сначала сохраните через UI.

Android БД и миграций нет. ONNX-копия не является пользовательским хранилищем: runtime проверяет её и при необходимости заменяет из assets. Фото/отчёт в памяти теряются после уничтожения процесса, поэтому штатное резервное копирование этих объектов не реализовано. Экспортированные JSON находятся у выбранного провайдера; их резервное копирование вне приложения. `allowBackup=false` запрещает рассчитывать на системный backup приватных данных как на процедуру проекта.

Сохраняйте проверенный APK и его Git SHA перед обновлением. Установка прежнего APK возможна лишь при допускаемых Android сочетаниях подписи/версии и требует повторной проверки. Проверенной процедуры отката между выпусками в репозитории нет; команда с принудительным downgrade/очисткой не предлагается. Это пробел развёртывания, отмеченный в [аудите](documentation-audit.md), а не подтверждённый release-процесс.

## Что отсутствует для публичного выпуска

[app/build.gradle.kts](../app/build.gradle.kts) задаёт release build type без minification, но не signing config; workflow собирает debug, не публикует AAB/магазинный релиз. Нет описанных хранителя ключей, канала дистрибуции, правил версионирования, матрицы поддерживаемых релизов и проверенного recovery/rollback. Придумывать эти процедуры по наличию `release` build type нельзя. Вопрос распространения сторонних весов требует отдельного решения по [лицензии модели](../ml/MODEL.md#1-происхождение-весов).

## Диагностика после установки

Логи, ошибки и проверка восстановления — [runbook](operations/runbook.md). Метрики собираются вручную через JSON диагностики; внешнего мониторинга, crash-upload и SLA нет. Полевое качество, нагрев и работа конкретных объективов проверяются по [протоколам](index.md#сохранённые-протоколы-и-исследования), а не по размеру APK или зелёной сборке.
