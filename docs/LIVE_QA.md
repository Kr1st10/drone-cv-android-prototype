# Проверка живой детекции 0.4.0

Аппаратная приёмка пока не выполнена. Ниже — инструкция, не результаты испытаний.
APK: artifact `app-debug` в Actions соответствующего PR или локальный `app/build/outputs/apk/debug/app-debug.apk`.
Установка: `adb install -r app-debug.apk` (arm64-v8a / x86_64, API 26+).

## Основной сценарий

1. Открыть **Камера**, разрешить CAMERA. До нажатия **Начать детекцию** виден preview, инференс не идёт.
2. Нажать **Начать детекцию**, дождаться загрузки YOLO11s. Навести на реальный дрон в безопасной сцене;
   отдельно проверить фон, птиц и самолёты. Рамки должны соответствовать объектам, содержать `drone` и confidence.
   Отсутствие рамок на сцене без дрона допустимо; модель может давать ложные срабатывания.
3. Изменить confidence (10–95%). Старые рамки сразу исчезают, следующие результаты используют новый порог.
4. Проверить обе альбомные ориентации, портрет и multi-window resize: рамка у края/в центре остаётся на объекте.
   Проверять на неподвижной сцене: рамки относятся к последнему обработанному кадру, движущийся объект
   и камера смещаются за время инференса. Трекинга и компенсации задержки нет.
5. Нажать **Остановить** во время инференса. Рамки/метрики очищаются сразу и не возвращаются от позднего ответа;
   preview продолжает работать. Повторный **Начать детекцию** возобновляет настоящий анализ.

## Жизненный цикл и ошибки

- Выполнить Home → возврат, блокировку → разблокировку и 10 быстрых поворотов при работе.
  В фоне анализ выключается, модель освобождается после текущего native call. При возврате возобновляется,
  если детекция была включена; старые рамки не возвращаются.
- Несколько раз переключить «Фото» ↔ «Камера» во время обработки. Фото/его результаты сохраняются;
  **Распознать** и выбор нового фото работают. Для камеры после смены вкладки запуск ручной.
- Проверить запрет CAMERA, «больше не спрашивать», выдачу/отзыв в настройках, занятую камеру, повтор открытия.
- Проверить большой шрифт и маленькое окно: панель управления прокручивается и кнопка доступна.
- После Stop сверить CPU/память с preview без анализа; после Home камера должна освободиться.
- Провести 10–15 минут анализа; записать нагрев, память и ошибки logcat. Одна конечная проверка памяти
  не доказывает отсутствия утечки — сравнивать одинаковые циклы запуска/остановки и устойчивый тренд.

## Метрики и замеры

- **Обработка FPS**: частота завершённых результатов в скользящем окне до 30 кадров/около 3 секунд,
  первый кадр ещё без FPS. Это не FPS камеры и не `1000 / inferenceMs`.
- **ORT**: вызов общего `runModel`: перенос входа в direct buffer, создание tensor, `session.run` и чтение выхода,
  как существующая метрика фото. Не включает пред-/постобработку.
- **Полный цикл**: от входа analyzer в backend до результата, включает RGB/crop, пред-/постобработку;
  первый кадр также включает загрузку/проверку модели. Время ожидания перед analyzer и задержка дисплея не входят.
- Число кадров и размер показываются только для реально обработанных кадров. При паузе статистика сбрасывается;
  при отсутствии свежего результата 1.5 с рамки и текущие тайминги скрываются.
- Для отчёта записать модель телефона, Android, версию APK, размер кадра, threshold, холодный запуск отдельно,
  затем FPS/ORT/полный цикл после прогрева и через 10 минут. Не переносить цифры эмулятора на телефон.

## Автоматизация

`./gradlew connectedDebugAndroidTest`: существующие decoder/EXIF/ORT тесты плюс настоящий UI-сценарий
CameraX → RGBA → YOLO11s → результат, Stop/restart, фон/возврат, recreation и оба landscape-направления.
Нужна задняя камера; отсутствие hardware явно пропускает camera-тесты через assumption.
CI запускает эти APK на API 29 x86_64 с эмулированной задней камерой. Это проверяет интеграцию,
но не физическую точность рамок, качество детектора, скорость/нагрев телефона и OEM lifecycle.
