# Приёмка сессии камеры на Android

Руководство для разработчика и тестировщика. Применяется к сборке, указанной в карточке прогона. Автоматические проверки подтверждают логику приложения; устойчивость камеры, задержку и нагрев целевого телефона проверяйте отдельно.

## Маршрут на телефоне

1. Зафиксируйте APK и его SHA-256, исходный Git SHA и наличие локального diff. Проверьте модель в APK командой из [инструкции сборки](../deployment.md). Не сравнивайте измерения только по versionName.
2. Включите камеру, выберите доступный недефолтный zoom или physical ID и запустите детекцию. Проверьте Stop/start, уход в фон и возврат, поворот и пересоздание Activity, переход «Камера → Фото → Камера». При восстановлении проверьте сначала **запрос**, затем фактические данные нового подключения. Если выбор недоступен, ожидается предупреждение и попытка 1×/auto. Переход через «Фото» оставляет ручной запуск, как описано в [lifecycle](../internals/detection-lifecycle.md).
3. Во время работы модели остановите и снова запустите камеру. Прежняя рамка не должна возвращаться; при потере наблюдения на экране не остаются актуальные координаты. Запустите и завершите запись, экспортируйте JSON. Если экспорт ещё идёт, начало новой записи не должно скрывать кнопку завершения или подменять её отчёт.
4. На одинаковой сцене запишите короткое раннее окно без усечения, длительную сессию (например, 15 минут как первый пилот) и короткое позднее окно. По возможности не перезапускайте камеру или модель между окнами. Прерывания отметьте. Экспортируйте между окнами или укажите его как часть нагрузки. Для движущейся цели подготовьте разметку, чтобы отличить потерю, захват фона и смену объекта.

Для условий нагрузки, прогрева и анализа используйте [PERFORMANCE_QA](../PERFORMANCE_QA.md). При смене устройства, сборки, сцены, настроек или режима питания явно отметьте отличие; успешный разбор JSON не доказывает сопоставимость.

## Карточка прогона

Скопируйте карточку рядом с APK и результатами. Если параметр недоступен, укажите `null` и причину. Сохраняйте одну строку на каждое окно; не смешивайте разные сборки и условия.

| Поле | Значение для прогона |
|---|---|
| Исходники | Git SHA; чистая или изменённая копия; для изменённой — сохранённый patch и его SHA-256 |
| APK | Имя, SHA-256, build type, versionName/versionCode |
| Модель | Имя, asset, SHA-256 |
| Устройство | Производитель, модель, Android/API; физический телефон или эмулятор |
| Запрос и фактическая камера | Запрошенные zoom/physical ID; подтверждённые zoom, logical/active physical ID или причина отсутствия; fallback |
| Обработка | Порог, потоки ORT, ориентация, размер анализа и upright crop |
| Условия | Сцена и движение, освещение, яркость, питание/заряд, прогрев, начальная температура батареи при доступности |
| Переходы | Время Stop/start, фона, rebind, поворота, ошибок; был ли перезапуск модели |
| Результаты | Имена и SHA-256 JSON, границы каждого окна, его длительность, признаки прерывания и усечения |

| Окно | Начало / конец | Файл | Вход, YOLO, обновления LK | Сохранено / не сохранено | Метки экспозиции, p50/p95 | Ресурсы / замечания |
|---|---|---|---|---|---|---|
| Раннее короткое | null | null | null | null | null | null |
| Длительное | null | null | null | null | null | null |
| Позднее короткое | null | null | null | null | null | null |

## Как читать результат

- Вход, завершения YOLO и обновления LK — три разных счётчика. Коррекция на том же изображении не увеличивает число кадров. Частота отчёта относится к полной длительности записи.
- p50/p95 относятся к сохранённым пригодным samples. При `tracking.unstored_samples > 0` сохраняется начало записи: его p95 нельзя выдавать за распределение всей длительной сессии. Раннее и позднее короткие окна не заменяют полную выборку.
- При UNKNOWN отсутствует измерение от экспозиции. Интервал от analyzer до сигнала не измеряет задержку дисплея; температура батареи не равна температуре CPU. Отсутствие данных не заменяйте нулём.
- Указывайте время без координат рядом с задержкой успешных обновлений. На размеченном видео отмечайте потери и ошибки идентичности отдельно от локального track ID.

Следующий шаг выбирайте по результату маршрута: сначала воспроизведите конкретный срыв перехода, если он возник. Если маршрут устойчив, снимите короткое позднее окно на том же устройстве и в тех же условиях, что раннее. Без него нельзя выбрать между изменением работы модели, памяти или окна метрик.
