# Непрерывность и свежесть координат

Офлайн-анализ для разработчика CV и автора ВКР. Вход: [поток NDJSON](../reference/data-model.md#поток-диагностической-сессии-dronecv-session-timeline-1). Реализация: `ml/scripts/timeline_analysis.py`, Python 3, стандартная библиотека. Анализатор использует существующий `read_timeline()`. Android, YOLO/LK и критерий движения не меняются.

## Запуск

Из корня репозитория:

```bash
python3 ml/scripts/timeline_analysis.py session.ndjson \
  --max-coordinate-age-ms 200 \
  --output continuity.json --episodes-csv episodes.csv
```

`--max-coordinate-age-ms` обязателен, default отсутствует: конечное неотрицательное десятичное число миллисекунд с точностью до целой наносекунды. Значение 200 здесь служит примером, а не требованием к приложению. JSON сохраняет эквивалентный целый порог с `unit=ns`. Все три пути должны различаться. Родительские каталоги должны существовать; результаты перезаписываются. Ошибка формата/параметра завершает CLI ненулевым кодом; корректно сформированный отчёт о неполных данных возвращает 0, поэтому автоматизация обязана проверять `scope`, `recording_complete` и `integrity_errors`.

Прежний `analyze_android_sessions.py` сохраняет свои режимы, чтение старых JSON и экспорт интервалов NDJSON. Новая команда предназначена для одной временной шкалы; парного A/B-сравнения здесь нет.

## Область анализа и арифметика

При достоверных границах используется весь полуоткрытый интервал `[header.start_ns, session_end.stop_ns)`, включая последний участок без событий. Нулевые интервалы игнорируются. Исходные строки времени переводятся в Python `int`; границы и длительности вычисляются целыми числами без `float`. В отчёте времена и длительности представлены JSON integer, идентификатор сессии остаётся строкой. Потребители JavaScript должны использовать парсер целых чисел произвольной точности для значений выше `2^53`; обычный `JSON.parse` может потерять точность.

`scope=bounded_recording` означает вычисления для заданного интервала записи, а не доказательство завершения внешнего эксперимента. `experiment_status` и исходный `session_end.interrupted` сохранены отдельно: прерывание не делает полный файл повреждённым. При отсутствии/некорректности конца, несогласованных границах или неоднозначных заголовках/концах выдаётся `scope=unavailable`, `stop_ns=null`, `metrics=null` и причина в `unavailable_reasons`. Время последнего события не заменяет конец записи. Диагностика наблюдаемого префикса отдельно не вычисляется.

Ошибки целостности читателя сохраняются; повреждённые или потерянные события консервативно делают состояние неизвестным на всём ограниченном интервале. `observed_box` не восстанавливает достоверные координаты. Достоверные границы могут существовать и при неизвестном состоянии внутри них.

## Состояния и доли

- `present`: читатель подтвердил состояние и рамка содержит четыре конечных числа `[left, top, right, bottom]` в `[0,1]` с положительными сторонами.
- `absent`: читатель подтвердил явное `box=null`.
- `unknown`: до первого состояния, при missing/invalid box либо при неопределённости читателя.

В `metrics.duration_ns` выполняется `present + absent + unknown = stop - start`. `time_fraction` содержит доли достоверно отнесённого к каждой категории времени относительно всей записи. `coordinate_availability.exact` задана только при нулевом неизвестном времени. Иначе она `null`, нижняя граница равна `present/duration`, верхняя `(present+unknown)/duration`. Это границы доступности, а не точная оценка. При нулевой длительности все доли и границы `null`.

До построения границы интервала читатель проверяет часы каждого `state`, включая очистку `box=null`. Явный `publication_clock`, отличный от `elapsed_realtime_ns`, либо явно несовместимый `header.clock` вызывает `ValueError` с номером строки; CLI завершает работу с ошибкой до записи отчёта и CSV. Такой файл не получает достоверных длительностей, долей доступности или эпизодов разрывов. Для исторических файлов схемы 1 отсутствие `publication_clock` или `header.clock` означает `elapsed_realtime_ns` по правилу совместимости; явно заданный `null` не считается отсутствующим полем.

Среди `present` отдельно суммируются `fresh`, `stale`, `age_unknown`; их сумма равна `present`. Время экспозиции пригодно только при `header.clock=elapsed_realtime_ns`, `timestamp_source=elapsed_realtime`, отсутствии `timing_issue` и `0 < capture_ns <= analyzer_entry_ns <= publication_ns`. Неизвестные часы экспозиции при пригодных часах публикации делают неизвестным возраст изображения и сохраняют известное наличие координат.

`age(t)=t-capture_ns`. Свежесть определяется как `age < threshold`. На `capture_ns+threshold` начинается устаревание, даже без новой публикации. Начальный снимок и повтор того же изображения сохраняют его возраст; коррекция использует собственный `capture_ns`, а не последнее подтверждение YOLO. Ни вход в анализатор, ни публикация не заменяют экспозицию. Это оценка свежести по аналитическому порогу, не восстановленный runtime `displayUntilNs`.

Для `fresh_coordinate_availability` неизвестное время равно `unknown+age_unknown`: точная доля либо `null`, границы `fresh/duration` и `(fresh+unknown+age_unknown)/duration`.

## Два ряда эпизодов

`coordinate_gaps` описывает максимальные непрерывные интервалы известного отсутствия координат после первого наблюдаемого наличия. `fresh_coordinate_gaps` описывает интервалы, когда координаты отсутствовали или устарели, после первого наблюдения свежих координат. Последовательные пустые публикации объединяются; переход отсутствия в устаревание не разрывает второй ряд. События `publication`, дублирующие `state`, не участвуют повторно.

Каждый ряд содержит `first_observation`, `summary`, `episodes`. Первое наблюдение означает «координаты появились», без доказательства первого захвата. `in_initial_snapshot` отмечает наличие уже в начальном снимке. `observed_wait_ns` отделяет начальное ожидание от последующих потерь; если координаты так и не появились, это длительность наблюдения с `wait_right_censored=true`. `wait_uncertain` предупреждает, что неизвестность могла скрыть более раннее появление.

Эпизод хранит начало, конец наблюдения, длительность, изменения состояния/причины, `recovered`, `recovery_ns`, `left_uncertain`, `right_uncertain`, `right_censored`, `duration_is_lower_bound`. Неизвестный участок завершает известный эпизод с `right_uncertain=true`. Он не доказывает потерю или восстановление. Следующий известный участок отсутствия начинается с `left_uncertain=true`; последующее возвращение координат наблюдается, но полная длительность такого разрыва неизвестна.

Для разрыва до `stop_ns`: `recovered=false`, `recovery_ns=null`, `right_censored=true`; длительность является нижней границей полной длительности. Окончание записи при наличии координат не создаёт потерю.

Сводка отдельно хранит число наблюдаемых эпизодов, достоверных начал (`observed_start_count`, исключает неопределённую левую границу), наблюдаемых восстановлений и незавершённых эпизодов до конца записи. При неизвестности `total_count_exact=false`, `total_count=null`: скрытые эпизоды возможны. `max_observed_duration_ns` включает цензурированные участки. Максимум и среднее полностью наблюдавшихся завершённых разрывов исключают оба неопределённых края и цензурирование. При отсутствии подходящих эпизодов значение `null`, не ноль.

## Выходы и пример

JSON имеет `schema=dronecv-coordinate-continuity-1`, SHA-256 всех байтов исходного файла и `session_id`: вместе они однозначно связывают результат с исходными метаданными приложения/камеры в журнале. Заголовок и конец дополнительно сохранены в отчёте. `unknown_reasons` и `unavailable_reasons` объясняют ограничения. Повтор с теми же байтами и параметром детерминирован, без текущего времени генерации.

CSV содержит оба ряда, тип разрыва, целые времена/длительность в ns, восстановление, цензурирование, неопределённость и JSON-массив переходов. Неизвестное значение записывается литералом `null`; в JSON это настоящий null. Консоль даёт краткую сводку, подробные доли и границы находятся в JSON.

Синтетический пример записи `[1000,2000)` мс с порогом 200 мс: начальный снимок с capture=900; повтор в 1200 с тем же capture; очистка в 1400; координаты в 1600 с capture=1500; очистка в 1800. Результат:

```text
Session synthetic: bounded_recording; complete=True; experiment=completed
Duration 1000000000 ns; present=600000000, absent=400000000, unknown=0 ns
Fresh=200000000, stale=400000000, age_unknown=0 ns
coordinate_gaps: observed starts=2, recoveries=1, unfinished=1, count_exact=True
fresh_coordinate_gaps: observed starts=2, recoveries=1, unfinished=1, count_exact=True
```

Доля наличия 0,6, доля свежести 0,2. Разрывы наличия `[1400,1600)` и `[1800,2000)` мс; свежести `[1100,1600)` и `[1700,2000)` мс. Второй разрыв каждого ряда цензурирован остановкой записи.

Синтетические тесты подтверждают вычисления. Без независимого эталона результат не доказывает правильность объекта LK, возвращение прежнего дрона, Recall, дальность или качество приложения на Xiaomi. Формулировка восстановления: «публикация пригодных координат восстановилась».
