# Этап 6.6 — лабораторный тест «телефон → экран»

Офлайн-галерея и манифест **90 реальных фотографий** для ручной проверки приложения на Xiaomi 17T Pro / 17 Pro: камера телефона наводится на экран MacBook или внешний монитор. Физический масштаб экрана измеряется линейкой, поэтому диагональ 13″ и разрешение 4K не являются обязательными исходными данными. Набор **только для тестирования**, в обучение и подбор порогов не передаётся.

| Категория (`category`) | Что на снимке | Кол-во |
|---|---|---|
| `civil_quadcopter` | гражданские квадрокоптеры в полёте | 20 |
| `military_uav` | военные БПЛА в небе: самолётного типа, малые квадрокоптеры, барражирующий боеприпас, катапультный запуск | 20 |
| `uav_payload` | БПЛА с видимой подвесной/внешней нагрузкой, **подтверждённой подписью источника** (`payload_evidence`) | 10 |
| `bird` | птицы в полёте | 15 |
| `aircraft` | самолёты и вертолёты | 15 |
| `negative` | небо, облака, ветки, горизонт без летящих объектов | 10 |

Все изображения — фотографии (не рендеры, без нарисованных рамок) с Wikimedia Commons под CC0, Public Domain, CC BY или CC BY-SA. Автор, лицензия, страница источника и SHA-256 каждого файла указаны в `manifest.json`. **Сами изображения в репозиторий не входят**: они скачиваются по манифесту с серверов Wikimedia.

Что такое `uav_payload`: на снимке видна нагрузка (бак/распылитель агродрона, груз на подвесе, контейнер, подвесной контейнер РЭБ, ракеты под крылом), и это прямо следует из подписи источника; цитата сохранена в `payload_evidence`. Назначение нагрузки по внешнему виду **не приписывается**, боевая часть не предполагается, если подпись этого не говорит.

## Файлы

- `gallery.html` — галерея, один файл, без сети и сборки.
- `manifest.json` — манифест (источник истины). `manifest.js` в репозитории нет: его создаёт `fetch_images.py` из `manifest.json` (браузер не даёт `file://`-странице читать JSON).
- `fetch_images.py` — загрузка изображений по манифесту с проверкой SHA-256 (только стандартная библиотека Python 3.8+).
- `PROTOCOL.md` — методика испытания, калибровка, что записывать.
- `results_template.csv` — столбцы экспорта CSV из галереи (описание — `PROTOCOL.md`, раздел 5).
- `build_manifest.py` — проверка манифеста (категории, количества, лицензии, рамки, независимость); `--write-js` пересоздаёт `manifest.js`. При обычном использовании не нужен.
- `tests/` — проверки манифеста, расчётов/экспорта, статические проверки и браузерные сценарии: `python3 -m pytest tests` (браузерные проверки пропускаются без Node+Playwright/Chromium и скачанных изображений).
- `PROJECT_STATE.md` — проверенное состояние этой задачи стенда и оставшиеся физические испытания.

## Как скачать и запустить

1. Получить папку: `git clone https://github.com/Kr1st10/drone-cv-android-prototype.git` (или «Code → Download ZIP» на GitHub и распаковать). Нужна только папка `lab/monitor_test/`.
2. Скачать изображения (≈ 90 файлов, около 167 МБ, несколько минут):
   ```bash
   cd drone-cv-android-prototype/lab/monitor_test
   python3 fetch_images.py          # Windows: py fetch_images.py
   ```
   Скрипт кладёт файлы в `images/` и создаёт `manifest.js`, повторный запуск докачивает только отсутствующие; `python3 fetch_images.py --verify` — только проверка. Итог должен быть `OK 90 / 90`. Если Wikimedia отвечает 429, скрипт сам делает паузы; можно увеличить `--delay 3`. Если когда-нибудь SHA-256 миниатюры перестанет совпадать (Wikimedia пересоздала её), файл переименуется в `*.sha256-mismatch`; тогда `python3 fetch_images.py --original` скачает оригиналы и проверит их по SHA-1 Commons — геометрия рамок пересчитывается автоматически (галерея масштабирует по `width/height` манифеста).
3. Открыть `gallery.html` в Chrome/Edge/Firefox на MacBook или компьютере с внешним монитором. Интернет больше не нужен. Страница файла на GitHub показывает исходник; запускать нужно скачанный HTML вместе с `manifest.js` и `images/`.
4. Задать масштаб браузера (для повторяемости — **100 %**, Cmd+0 / Ctrl+0), перенести окно на нужный дисплей и включить полный экран (**F**). Для физического эксперимента сделать это **до калибровки линейкой**. `devicePixelRatio` используется для экранных px, но не заменяет измерение мм.
5. Провести испытание (ниже — пилот за две минуты, подробности — `PROTOCOL.md`); в конце — «Экспорт CSV» и «Экспорт JSON».

Готовый архив «галерея + изображения» можно сделать после загрузки, выполнив из корня репозитория
`zip -r monitor_test.zip lab/monitor_test` (шаг 2 переводит shell внутрь `lab/monitor_test`, сначала вернитесь
в корень). Архив с загруженными изображениями работает офлайн; результаты браузера переносите отдельным JSON.

## Пилот на 20 фото за две минуты

1. Открыть `gallery.html` → режим **«Быстрый тест»** (включён по умолчанию).
2. Нажать **«Пилот — 20 фото»**: фиксированная выборка 5/5/3/3/2/2 (гражданские / военные / с нагрузкой / птицы / самолёты / без объектов), seed 66020. На любом компьютере это одни и те же 20 изображений; код выборки (например, `S0d95e824`) показан в настройках.
3. Указать телефон, зум **1×** и измеренное расстояние от камеры до плоскости экрана, см → **«Начать прогон»** → **F**. Неизмеренное расстояние можно оставить пустым (`null`).
4. Для каждого снимка: навести телефон, подождать 2–3 с, нажать **R** и выбрать **1** «рамка на показанном объекте», **2** «рамка только в другом месте» или **3** «рамок нет» — результат сохраняется сразу. Перед выбором 1/2 можно ввести **«Максимальный confidence YOLO (%)»**, 0–100, включая дробные: максимум на объекте для 1, максимум ошибочной рамки в другом месте для 2. Пустое поле и вариант 3 дают `null`. Подробности — [поля записи](PROTOCOL.md#дополнительные-поля-записи). **A** — посмотреть правильный ответ (только после записи), **→** — следующий снимок.
5. После 20-го снимка: **S** → зум **5×** (при необходимости другое расстояние) → **«Начать прогон»**. Будут показаны **те же 20 изображений в том же порядке**.
6. **S** → «Экспорт CSV» и «Экспорт JSON». В CSV строки 1× и 5× различаются по `camera_zoom`, а `image_id` у них совпадают.

Своя выборка: ввести количества по категориям (например, 5/5/3/3/2/2 или 10/10/5/5/5/5) и seed → «Сформировать выборку по количествам». Одинаковые количества и seed всегда дают одну и ту же выборку. Выборка, прогоны и результаты хранятся в браузере (`localStorage`) и переживают перезапуск; «Экспорт JSON» сохраняет их в файл. Импорт переносит выборку/текущий прогон и добавляет отсутствующие прогоны/результаты; существующие записи не перезаписываются, корневые настройки надо проверить вручную. Подробности — [протокол экспорта](PROTOCOL.md#5-размеры-и-экспорт).

## Режимы

- **Быстрый тест** — нужны только модель телефона, 1×/5×, расстояние и результат обнаружения (1/2/3). Снимок в масштабе «вписать в экран», объект — в центре экрана (при 5× камера видит центр). Дополнительные confidence расширенного режима, ложные рамки и размеры в кадре не спрашиваются и сохраняются как пустые (`null`, «не измерено»).
- **Расширенный режим** — уровни размера объекта в px или см экрана, повторные попытки, калибровка камеры (**C**) и экрана линейкой, подтверждение границ объекта, параметры эталона, confidence, ручные размеры в кадре анализа, заметки. Пустое измерение — `null`. Физический режим требует актуальной калибровки экрана и подтверждённых границ объектов выборки.

## Эксперимент с дальностью для 10″ коптера

1. В расширенном режиме нажмите **«Калибровка экрана линейкой»**, измерьте контрольную линию в мм и сохраните замер. Коэффициент — мм на один CSS px. После перезагрузки/импорта, смены дисплея, масштаба или окна повторите измерение; сохранённый коэффициент сам по себе не подтверждает текущий экран.
2. Выберите снимок, нажмите **«Проверить / выделить границы»**, обведите именно коптер или исправьте координаты и подтвердите. Границы сохраняются для повторного использования; приблизительная рамка манифеста остаётся предложением. **«Выборка: только этот снимок»** позволяет исследовать его на нескольких уровнях.
3. Заполните модель эталона, **реальную ширину (см)** и источник. 10″ — диаметр пропеллеров, а не ширина аппарата. Если модель/габарит не установлены, оставьте статус неподтверждённым либо выберите явно **условный эталон** для отладки; не представляйте его как реальное измерение. Эталон относится только к выбранному снимку.
4. Измерьте расстояние от объектива камеры до плоскости экрана. Выберите **«ширина коптера = N см экрана»**, уровни, например **6,4,3,2,1**, **10 попыток**, критерий **90 %** и минимум **10 попыток**. Начните прогон. Ширина автоматически пересчитывается из подтверждённых границ и масштаба экрана; повторно мерить линейкой каждый уровень не требуется.
5. В **R** запишите обнаружение, confidence и измеренные ширину/высоту объекта в **кадре анализа камеры**, если они доступны. Пиксели браузера не подставляются вместо камерных. Необязательный ручной замер ширины на экране имеет приоритет над расчётом; экспорт сохраняет оба значения. **G** показывает/скрывает текущие мм и эквивалентную дальность; перед наблюдением скрывайте служебный текст.
6. Повторите серию для **5×**, заново проверив калибровку камеры и размер кадра анализа. В **S** доступны сводки по размеру и повторным попыткам: TP/доля, median confidence по известным обнаружениям, ширина в px, дальность и достижение критерия. Негативы учитываются отдельно как FP. Экспортируйте CSV и JSON.

Эквивалентная дальность: `drone_width_cm × distance_cm / (screen_object_width_mm / 10) / 100`. **Условный пример:** 60 см, 150 см, 3 см на экране → **30 м**. Без обязательного измерения результат — `null`. Методика, единицы, ограничения геометрии и поля экспорта описаны в [протоколе 1×/5×](PROTOCOL.md#короткий-эксперимент-для-10-дюймового-коптера-1-и-5).

CSV/JSON сохраняют исходные измерения, снимок калибровки и границ, источники камерных размеров, статус эталона и вычисления. Прежние JSON импортируются без новых полей. В JSON есть `size_summary` и `repeat_summary`; подробности — [размеры и экспорт](PROTOCOL.md#5-размеры-и-экспорт).

Эквивалентная дальность не подтверждает реальную дальность обнаружения. Принадлежность фотографий набора к конкретной 10″ модели не установлена: снимок, источник габарита и соответствие ракурса подтверждает оператор.

Размеры объекта — три разные величины:

| Поле | Единица | Откуда |
|---|---|---|
| `object_monitor_px` | px монитора | большая сторона подтверждённой рамки, иначе приблизительной рамки манифеста, с учётом масштаба показа; у пустого фона — `null` |
| `object_camera_px_expected` / `object_camera_px_measured` | px кадра анализа камеры | по калибровке `k` / по измерению на скриншоте; без них — `null` |
| `object_yolo_px` | px входа YOLO (640) | px кадра × min(640 / ширина кадра, 640 / высота кадра), letterbox; при кадре 640×480 совпадает с px кадра; без калибровки и измерения — `null` |

## Клавиши галереи

| Клавиша | Действие |
|---|---|
| → / Пробел, ← | следующее / предыдущее изображение |
| R | записать результат: 1 / 2 / 3 (ответ при этом не показывается) |
| A | правильный ответ — только после сохранения результата; до этого — подсказка «нажмите R» |
| F | полный экран (до калибровки линейкой) |
| G | текущая физическая ширина и эквивалентная дальность (расширенный режим) |
| S или Esc | настройки (выборка, прогон, экспорт) |
| + / − , 0 | ручной масштаб / сброс (расширенный режим) |
| C | калибровочные квадраты (расширенный режим) |
| I | служебная строка: номер, телефон, зум, масштаб; размер объекта — только после записи |

Во время наблюдения скрывайте служебные размеры (**G**) и HUD (**I**): снимок должен быть без подписей, рамок, идентификаторов и ответов. Результаты классифицируются после записи: для дронов «рамка на объекте» — TP, иначе FN; для птиц, самолётов и пустого неба любая рамка — FP, «рамок нет» — TN (`result_class`, `false_alarm`).

Поле порога в настройках галереи — запись условий, оно не управляет Android-приложением. В quick-режиме
поле скрыто и порог прогона сохраняется как null. Запишите его отдельно либо заполните в advanced
по [протоколу](PROTOCOL.md#1-установка). Техническая навигация по
приложению и стенду — [docs/index.md](../../docs/index.md).

## Независимость от прежних данных

Ни один снимок не взят из наборов, на которых обучался или проверялся baseline. Проверка (`independence` в манифесте): dHash-64 и миниатюры 16×16 каждого снимка сравнены со всеми 54 076 изображениями pathikg (train+test, rev `004b46cc`) и 10 000 изображениями DUT-Anti-UAV (train/val/test); совпадений нет (порог — см. `manifest.json → independence`). Halmstad, UAVDB, Anti-UAV300, UAV-CB и VDD — собственные видеозаписи этих проектов на конкретных площадках, а не фотографии с Commons, поэтому пересечение исключено по происхождению. Внутри набора почти-дубликатов нет, на одного автора/серию — не более 3 снимков.

## Ограничения

- Снимок на мониторе — не реальная сцена: экран добавляет муар, ограничение яркости и контраста, отражения; камера фотографирует плоскость. Результат показывает поведение модели на объекте заданного **размера в кадре анализа**, а не дальность обнаружения реального дрона.
- Размер объекта на мониторе (px/мм) и размер в кадре камеры — разные величины; связь между ними задаёт калибровка конкретной установки (телефон, зум, расстояние).
- Исходные рамки `object_bbox` приблизительные — для масштабирования и центрирования, не для IoU. Автоматическая физическая ширина использует только границы, подтверждённые оператором в редакторе.
- Лицензии CC BY / CC BY-SA требуют указывать автора при публикации кадров или скриншотов — данные есть в манифесте и в ответе галереи (клавиша A после записи).
