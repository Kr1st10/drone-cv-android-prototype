# Этап 6.6 — лабораторный тест «телефон → экран»

Офлайн-стенд для исследования YOLO11s на Xiaomi 17 Pro: существующая галерея **90 фотографий**, пилот на 20, собственные наборы, отдельное исследование предела и сохранённые результаты. Камера смартфона снимает экран MacBook или внешний монитор. Диагональ 13″ не заменяет калибровку линейкой. Набор **только для тестирования**, в обучение и подбор порогов не передаётся. Основная инструкция **«Как пользоваться?»** встроена в галерею; этот файл дополняет её.

Дополнительная вкладка **«Эксперимент с эталонными БПЛА»** содержит Skydroid MX330T (578,5 × 528,7 мм), UNIK SD-10UFP (590 × 530 мм, включая антенну) и GEDZ 10 DJI (500 × 419 мм). Выберите модель и одну из трёх фотографий, введите один раз расстояние до экрана, меняйте масштаб ползунком/числом или кнопками ×½/×2. Калибровка и расстояние общие с прежним стендом; повторный замер при переходе между вкладками не требуется. После перезагрузки действует прежнее явное подтверждение той же установки. При смене дисплея/геометрии окна нужен новый замер.

По умолчанию выбран режим **«Приближённая оценка»**: для трёх необрезанных изображений Skydroid и GEDZ показывается `≈ X,XX м` с явным допущением о ракурсе, модели и обрезке исходника. UNIK остаётся в списке с пустым состоянием и не блокирует другие модели. Внешние изображения не запрашиваются. **«Строгий: подтверждённая ось»** сохранён: у текущих изображений оси не подтверждены, поэтому в нём метры недоступны.

Оба режима используют формулу `D_equiv_m = W_real_cm × D_screen_cm / (W_display_cm × 100)` и существующую калибровку. Приближённый режим измеряет горизонтальную ширину видимого коптера по его собственной разметке, без полей файла; физический габарит выбирается по ракурсу. Соответствия, размеры и ограничения каждого изображения — в [описании фотографий](reference_assets/README.md#приближённый-режим--2026-11-08). При обрезке окном, неверных размерах файла, неизвестной калибровке или расстоянии метры не показываются. Для обрезанных исходников метры заблокированы: видимая часть не приравнивается полному габариту. В `skydroid_top` добавлен проверяемый отрезок между моторными центрами с координатами и экранной длиной; его физическая длина не подтверждена и не используется для дальности. Физический замер линейкой оператором пока не выполнен. Это расчёт углового размера с допущениями, не точная дальность и не результат YOLO.

Текущие ID модели/фото, режим (`range_mode`), ракурс, масштаб, расстояние, экранная длина проверяемого отрезка (`review_segment_display_mm`), принятый габарит (`assumed_extent_mm`), допущение и расчёт доступны через `referenceTab.snapshot()` в консоли страницы. Выбор модели, фотографии, режима и масштаб хранятся в отдельном ключе `dronecv66v2.reference_tab`; прежние сессии и формат экспорта не меняются. Настройки новой вкладки не включаются в прежний JSON, а расстояние и калибровка переносятся его существующими полями.

| Категория (`category`) | Что на снимке | Кол-во |
|---|---|---|
| `civil_quadcopter` | гражданские квадрокоптеры в полёте | 20 |
| `military_uav` | военные БПЛА в небе: самолётного типа, малые квадрокоптеры, барражирующий боеприпас, катапультный запуск | 20 |
| `uav_payload` | БПЛА с видимой подвесной/внешней нагрузкой, **подтверждённой подписью источника** (`payload_evidence`) | 10 |
| `bird` | птицы в полёте | 15 |
| `aircraft` | самолёты и вертолёты | 15 |
| `negative` | небо, облака, ветки, горизонт без летящих объектов | 10 |

Все 90 изображений прежней галереи — фотографии (не рендеры, без нарисованных рамок) с Wikimedia Commons под CC0, Public Domain, CC BY или CC BY-SA. Автор, лицензия, страница источника и SHA-256 каждого файла указаны в `manifest.json`. **Сами изображения в репозиторий не входят**: они скачиваются по манифесту с серверов Wikimedia.

Что такое `uav_payload`: на снимке видна нагрузка (бак/распылитель агродрона, груз на подвесе, контейнер, подвесной контейнер РЭБ, ракеты под крылом), и это прямо следует из подписи источника; цитата сохранена в `payload_evidence`. Назначение нагрузки по внешнему виду **не приписывается**, боевая часть не предполагается, если подпись этого не говорит.

## Как скачать и запустить

1. Получить папку: `git clone https://github.com/Kr1st10/drone-cv-android-prototype.git` (или «Code → Download ZIP» на GitHub и распаковать). Нужна только папка `lab/monitor_test/`.
2. Скачать изображения (≈ 90 файлов, около 167 МБ, несколько минут):
   ```bash
   cd drone-cv-android-prototype/lab/monitor_test
   python3 fetch_images.py          # Windows: py fetch_images.py
   ```
   Скрипт кладёт файлы в `images/` и создаёт `manifest.js`, повторный запуск докачивает только отсутствующие; `python3 fetch_images.py --verify` — только проверка. Итог должен быть `OK 90 / 90`. Если Wikimedia отвечает 429, скрипт сам делает паузы; можно увеличить `--delay 3`. Если когда-нибудь SHA-256 миниатюры перестанет совпадать (Wikimedia пересоздала её), файл переименуется в `*.sha256-mismatch`; тогда `python3 fetch_images.py --original` скачает оригиналы и проверит их по SHA-1 Commons — геометрия рамок пересчитывается автоматически (галерея масштабирует по `width/height` манифеста).
3. Открыть `gallery.html` в Chrome/Edge/Firefox на MacBook или компьютере с внешним монитором. Интернет больше не нужен. Страница файла на GitHub показывает исходник; запускать нужно скачанный HTML вместе с `experiment.js`, `manifest.js` и `images/`.
4. Задать масштаб браузера (для повторяемости — **100 %**, Cmd+0 / Ctrl+0), перенести окно на нужный дисплей и включить полный экран (**F**). Для физического эксперимента сделать это **до калибровки линейкой**. `devicePixelRatio` используется для экранных px, но не заменяет измерение мм.
5. Открыть встроенную инструкцию **«Как пользоваться?»**. Для первого запуска нужны два числа: длина контрольной линии в **см** и расстояние от объектива камеры до экрана в **см**. Затем выбрать «Галерея и сравнение» или «Измерить предел». Технические параметры находятся в «Дополнительно».

Готовый архив «галерея + изображения» можно сделать после загрузки, выполнив из корня репозитория
`zip -r monitor_test.zip lab/monitor_test` (шаг 2 переводит shell внутрь `lab/monitor_test`, сначала вернитесь
в корень). Архив с загруженными изображениями работает офлайн; результаты браузера переносите отдельным JSON.

## Первый запуск и исследование

1. На нужном дисплее включите fullscreen **F**. Нажмите **«Калибровка экрана»**, измерьте расстояние между двумя высокими вертикальными рисками и введите длину в **см**. Линия находится в видимой области и адаптируется к ширине окна. Введите измеренное расстояние от объектива смартфона до экрана.
2. В **«Измерить предел»** уже выбран профиль **Draganfly Flex FPV 10**: пропеллеры 10″, габариты 570 × 570 × 60 мм, номинальная ширина 57 см для соответствующего ракурса. Источники: [производитель](https://draganfly.com/flex-fpv-system/) и [брошюра, стр. 11](https://draganfly.com/wp-content/uploads/2026/02/DPRO-Product-Brochure-Feb-2026.pdf#page=11).
3. Загрузите **свой допустимый снимок** PNG/JPEG/WebP до 20 МБ, подтвердите модель/проекцию и один раз выделите именно коптер. Хранится подготовленная копия с большей стороной до 2048 px и её границы. Готового распространяемого эталонного фото с подтверждённой проекцией 57 см в поставке нет: официальные перспективные фото не приравниваются к полному габариту.
4. Для оси **px камеры** один раз выполните калибровку камеры **C** и проверьте её по второму квадрату; подтвердите актуальные телефон, зум, расстояние и размер кадра. Это отдельный замер, не перевод CSS px в пиксели камеры. Доступен также ручной замер истинной ширины по скриншоту в «Дополнительно» записи.
5. Начните готовую серию: **6,4,3,2,1,0.5 см**, по **20 отдельных проверок**. Запустите YOLO на смартфоне, фиксируйте заранее выбранный кадр после стабилизации и записывайте его результат **R → 1/2/3**; лучший кадр за окно не выбирайте. Импорт Android JSON для текущей проверки доступен в форме R; правильность рамки подтверждается вручную. Файл со множеством соседних кадров не становится множеством независимых испытаний.
6. В **«Результаты»** автоматически появятся график, числа TP/FN/FP и оценка перехода по фактически испытанным размерам. До проверок график пуст. Критерий исследования — **≥90 % при ≥20 независимых проверках на уровне**; независимость обеспечивает методика, а не флажок интерфейса. «Добавить промежуточный размер» добавляет ещё 20 проверок между уровнями перехода либо на меньшем уровне.
7. Проведите отдельную серию **5×**, проверив k и условия. Экспортируйте CSV/JSON, при необходимости SVG графика. Кнопки продолжения восстанавливают соответствующий сохранённый прогон; новую серию не нужно начинать при каждом открытии страницы.

Для новой физической установки нужен новый замер экрана и новый прогон. Если после открытия страницы дисплей, масштаб и геометрия окна действительно те же, доступно явное **«Экран и масштаб те же — подтвердить»** без повторного ввода длины. Браузер не гарантирует распознавание смены физического дисплея: при сомнениях повторите измерение. Подробности — [протокол](PROTOCOL.md).

## Пилот на 20 фото за две минуты

В **«Галерея и сравнение»** выберите «Пилот — 20 фото» (5/5/3/3/2/2, seed 66020, код `S0d95e824`), телефон/зум → «Начать прогон». **R → 1/2/3** сохраняет ответ, **A** открывает категорию только после записи, **→/←** переключают снимки. Перед ответом можно указать confidence; для «рамок нет» он остаётся null. Повторное R исправляет прежний ответ без создания новой проверки.

«Все 90 фото» и **«Свой набор»** с количествами категорий/seed сохранены. Переключение на исследование не удаляет галерею и её ответы. Прежние quick/advanced, px-масштабы и ручные корректировки доступны в **«Дополнительно»**. Для сравнения 1×/5× начинайте отдельные прогоны одной выборки.

## Галерея и сохранённый предел

Если границы текущего объекта ещё не подтверждены, один раз задайте их кнопкой **«Границы текущего объекта»**. **+/−/0** изменяют масштаб. **G** показывает физическую ширину, эквивалентную дальность и сравнение с выбранным сохранённым исследованием; перед наблюдением G скрывает подписи и кнопки; выключите также I и закройте формы.

Для неизвестной модели используется явное предположение **«считаем коптер шириной 57 см»**, которое можно изменить в «Дополнительно». Пример: 57 см, расстояние 150 см, ширина на экране 3 см → **28,5 м**. Это дальность такого углового размера для выбранного габарита, не расстояние до неизвестного дрона при исходной съёмке.

Сравнение с порогом требует достоверного размера в **кадре камеры**, совпадающих модели/SHA, телефона, камеры/зума, разрешения, confidence и NMS. Неизвестные или различающиеся параметры дают ориентировочный результат либо отсутствие сравнения. Размер выше порога не гарантирует обнаружение другой фотографии.

## Движущаяся цель

1. Откройте вкладку **«Движущаяся цель»**, загрузите фото или выберите имеющееся. Выделите границы дрона тем же редактором, что в галерее.
2. Задайте ширину дрона в пикселях экрана, предельную скорость и ускорение. Если всё фото не помещается в области движения, уменьшите ширину цели.
3. Закрепите телефон так, чтобы в его кадр попадали код и все четыре угловые метки. Запишите положение телефона и настройки камеры. Для A подготовьте конфигурацию приложения с YOLO, для B — с YOLO + LK. Используйте сопоставимые конфигурации с одинаковыми настройками камеры и модели.
4. Запустите полноэкранный прогон. Перед первым движением и в конце экран показывает фазу без цели. Для второго режима пары повторите сценарий с тем же фото, положением телефона и настройками. Следующая пара меняет порядок: A → B, затем B → A.
5. Выгрузите JSON эталона до закрытия вкладки. Отчёт Android, IoU и выбор прошедшего ускорения в этой версии не рассчитываются.

Код метки, единицы и поля JSON описаны в [протоколе движения](PROTOCOL.md#7-движущаяся-цель). Для этого режима не требуется калибровка линейкой: она нужна, когда результат выражают в миллиметрах, а не в пикселях.

## Сохранение и файлы результатов

Результаты, свои снимки, границы, параметры и графики сохраняются в браузере. В **«Результаты»** можно сохранить набор, экспортировать полный CSV/JSON, JSON выбранного исследования и SVG графика. JSON — резервная копия и перенос, включая подготовленный снимок. Исходные записи — источник статистики; импортированные графики/пороги пересчитываются, а не принимаются на веру.

Формат JSON `dronecv66-session-2` и импорт прежних сессий сохранены. CSV содержит 74 столбца; отсутствующее измерение — пустая ячейка/null. Источники, ограничения импорта, калибровок и статистики — [размеры и экспорт](PROTOCOL.md#5-размеры-и-экспорт).

## Клавиши галереи

| Клавиша | Действие |
|---|---|
| → / Пробел, ← | следующая / предыдущая позиция |
| R | записать или исправить ответ |
| A | категория/итог только после записи |
| F | полный экран до калибровки |
| G | физические размеры, дальность и сравнение |
| S / Esc | настройки и разделы стенда |
| + / − / 0 | изменить / сбросить масштаб |
| C | калибровка камеры |
| I | служебная строка |

## Независимость от прежних данных

Ни один снимок не взят из наборов, на которых обучался или проверялся baseline. Проверка (`independence` в манифесте): dHash-64 и миниатюры 16×16 каждого снимка сравнены со всеми 54 076 изображениями pathikg (train+test, rev `004b46cc`) и 10 000 изображениями DUT-Anti-UAV (train/val/test); совпадений нет (порог — см. `manifest.json → independence`). Halmstad, UAVDB, Anti-UAV300, UAV-CB и VDD — собственные видеозаписи этих проектов на конкретных площадках, а не фотографии с Commons, поэтому пересечение исключено по происхождению. Внутри набора почти-дубликатов нет, на одного автора/серию — не более 3 снимков.

## Ограничения

- Снимок на мониторе — не реальная сцена: экран добавляет муар, ограничение яркости и контраста, отражения; камера фотографирует плоскость. Результат показывает поведение модели на объекте заданного **размера в кадре анализа**, а не дальность обнаружения реального дрона.
- Размер объекта на мониторе (px/мм) и размер в кадре камеры — разные величины; связь между ними задаёт калибровка конкретной установки (телефон, зум, расстояние).
- Исходные рамки `object_bbox` приблизительные — для масштабирования и центрирования, не для IoU. Автоматическая физическая ширина использует только границы, подтверждённые оператором в редакторе.
- Лицензии CC BY / CC BY-SA требуют указывать автора при публикации кадров или скриншотов — данные есть в манифесте и в ответе галереи (клавиша A после записи).
