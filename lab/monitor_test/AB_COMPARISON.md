# Парное A/B-сравнение

Первый этап сравнивает отдельные прогоны и оценивает пригодность данных. Он не выбирает победителя, не присваивает общий балл и не определяет предельную скорость. Android-приложение не изменяется.

## Выполнить серию

1. Откройте `gallery.html` через локальный HTTP-сервер по [инструкции стенда](README.md). В разделе «Движущаяся цель» выберите фотографию, подтвердите границы объекта, настройте движение и заполните известные условия установки камеры.
2. Переключите режим на «A/B-сравнение». Выберите один фактор: режим приложения, сборка/профиль, скорость или ускорение. Для режима укажите `yolo` и `yolo_lk`; описание оператора сохранится отдельно от подтверждения журналом. Для сборки нужен точный `git_sha`, который записывает телефон. Профиль задаётся JSON с одинаковыми ключами у A и B, например `{"confidence":0.25}` и `{"confidence":0.40}`. Поддерживаются доступные поля метаданных телефона; отсутствие поля сохраняется как неизвестное.
3. Задайте число пар и нажмите «Создать серию из текущих настроек». По умолчанию предложены три пары, что не гарантирует достаточность эксперимента. Настройки вариантов фиксируются; дальнейшие изменения полей формы не меняют серию. Планы фиксируются при первом запуске соответствующего варианта. Для режимов и сборок используется один план.
4. Следуйте подсказке, например: «Пара 2 из 3. Вариант B. Подготовьте телефон и начните запись». Самостоятельно установите нужный режим или сборку телефона и включите запись. Затем явно нажмите «Запустить следующий вариант». Порядок заранее задан: AB, BA, AB, BA. Запуск телефона браузер не подтверждает.
5. После окончания остановите запись на телефоне. Для следующего варианта снова подготовьте телефон и нажмите кнопку запуска. «Стоп», Esc, скрытие страницы или изменение окна оставляют неполную попытку. Повтор выбранного варианта создаёт новый `run_id`, сохраняя план и записывая новые RAF samples и интервалы кода.
6. Загрузите журналы обычным импортом «Журналы Android». Используются существующие JSON/NDJSON-импортёры, подбор эталона по экранному ID и калибровка JPEG. При необходимости укажите четыре точки вручную. Для каждой пары явно выберите попытку A и попытку B в таблице. Лучший результат автоматически не выбирается.
7. Просмотрите причины ограничений, таблицы и сводку. Сохраните «Экспорт A/B JSON с исходниками» и CSV. Перезагрузка восстанавливает выбранную серию, порядок, попытки, привязки и анализы. JSON можно восстановить в чистом профиле браузера.

Одиночный режим сохраняет кнопки «Старт», «Стоп», «Повторить». В A/B камера, скорость и ускорение не переключаются автоматически на телефоне. Для ретроспективы явно введите два разных `run_id` сохранённых эталонов и нажмите «Объединить явно выбранные прогоны». Текущая фотография формы для этого не требуется. Порядок такой пары отмечен как незапланированный.

## Сопоставимость

Браузер сопоставляет SHA фотографии, разметку и размер исходника, размер цели, маршрут, круги, рабочую область, sync-параметры, viewport, снимки исходных настроек и доступные сведения телефона. Установка камеры включает введённые оператором условия; они не являются автоматическим измерением. Неизвестное значение, в том числе внутри объекта, не доказывает равенство даже при отсутствии у обеих сторон.

При изменении скорости или ускорения допускаются выбранный исходный параметр и производные времена движения. Остальные исходные параметры сравниваются. При сравнении режима журнал должен подтвердить ожидаемый режим каждой стороны. При сравнении сборки проверяется её идентификатор; сопутствующие версия, version_code и build_type могут отличаться. Для профиля допускается разница только в объявленных ключах. В остальных сравнениях эти сведения о сборке должны совпадать. Неизвестный `git_dirty` или сборка с локальными изменениями не подтверждают идентичность по одному `git_sha`. Остальные доступные поля, геометрия камеры, подтверждённый zoom и logical ID проверяются отдельно. Изменение телефона после калибровочного кадра самим журналом не исключается.

Причины показываются явно: ожидается журнал A/B, запись прервана, условия не подтверждены, данные несопоставимы или отдельная метрика недоступна. Неизвестные описательные поля не мешают движению, но исключают неподтверждённую пару из сводки пригодных пар. Неполные журналы, несовместимая синхронизация и разные версии критериев также ограничивают сравнение. Старые пороги и максимумы `motion-retention-v3` к `motion-scenario-v5` не применяются.

Повторный импорт одинаковых байтов под другим именем использует прежний SHA-256 и не создаёт повторение. Чужие или неоднозначные ID, конфликтующие эталоны и разное содержимое одного ID отклоняются с причиной. Они не назначаются A/B по имени файла или порядку загрузки. При конфликте исходная привязка остаётся сохранённой.

## Читать отчёт

Таблица каждой пары содержит метрику, A, B, разницу B−A и ограничения. Временные доли и события берутся из существующего анализатора сценария. Условная ошибка центра сопровождается покрытием; задержка экспозиция→публикация вычисляется по всему журналу, включая подготовку и завершение, только для согласованных timestamps. Она сопровождается числом пригодных публикаций и их долей, отдельно для YOLO и LK. Это публикация координат, а не время появления рамки на дисплее.

Для интервалов `[a₁;a₂]` и `[b₁;b₂]` разница равна `[b₁−a₂;b₂−a₁]`. Для долей она выражена в процентных пунктах. Середина интервала не становится точным измерением. `null`, цензурированное событие и отсутствие знаменателя не превращаются в ноль.

Контрольный расчёт ниже синтетический, он не является испытанием телефона. При 83% правильного перекрытия на оценённых 66,6% видимого времени получаются:

| Величина | A | B при программном A/A | Разница B−A |
|---|---:|---:|---:|
| Условное правильное перекрытие | 83% | 83% | 0 п.п. |
| Покрытие | 66,6% | 66,6% | 0 п.п. |
| Подтверждённо правильное время | 55,278% | 55,278% | 0 п.п. |
| Неправильное время | 11,322% | 11,322% | 0 п.п. |
| Неизвестное время | 33,4% | 33,4% | 0 п.п. |
| Правильное удержание за всё видимое время | 55,278–88,678% | 55,278–88,678% | −33,4…33,4 п.п. |

После округления общие границы составляют 55,3–88,7%. Для двух одинаковых интервалов захвата 59–420 мс разница составляет −361…361 мс. Программное A/A проверяет арифметику; аппаратная повторяемость требует независимых реальных прогонов.

Сводка показывает все запланированные пары, выполненные и пригодные пары, выбранные попытки и причины исключения. Единица повторения: пара. Для каждой доступной сопоставимой разности рассчитываются число пар, медиана, минимум и максимум. Нижние и верхние границы интервалов агрегируются отдельно. Медиана разностей p95 отдельных прогонов не является p95 объединённых кадров.

## Экспорт и хранение

`dronecv-motion-ab-bundle-1` содержит серию `dronecv-motion-ab-series-1`, фактор, варианты, происхождение описаний, снимки настроек и планов, попытки, плановый/фактический порядок, ручной выбор, привязки, неизменённые исходные журналы в `raw`, их разобранные данные, эталоны с фактическими RAF/sync, сохранённые результаты и параметры калибровки. Каждый анализ имеет версию `motion-ab-analysis-v1`, версию критерия и время создания. Пересчёт сохраняет новый результат при изменении данных или параметров; идентичный расчёт не дублируется.

Манифест указывает ID и SHA-256 журналов по исходным UTF-8 байтам и эталонов по каноническому JSON с сортированными ключами. `integrity` проверяет полный комплект без самого поля `integrity`. Контрольные суммы обнаруживают случайные изменения; это не электронная подпись. CSV хранит строки пар и метрик, включая JSON-представления интервалов, статусов и причин. Полный JSON нужен для воспроизведения анализа, CSV не заменяет исходники.

Для повторного расчёта найдите `analysis.source_hash` в `series.journals`, прочитайте `raw` существующим импортёром, найдите эталон по `analysis.run_id` и вызовите `MotionReportV4.analyze(run, journal, analysis.parameters.calibration_points)`. В `analysis.result.criterion_version` сохранена версия критерия. Обычный импорт журналов и ручная калибровка позволяют повторить этот расчёт в интерфейсе; исторические результаты остаются в серии.

Метаданные запуска, снимок настроек и принадлежность к серии сохраняются одной IndexedDB-транзакцией до первого RAF. Завершение эталона и попытки также атомарно. Отказ fullscreen до запуска остаётся отдельной неуспешной попыткой без фиктивного эталона. После аварийной перезагрузки незавершённый запуск не становится полным.

Ограничения: до 8 сохранённых серий, до 64 анализов суммарно, до 64 МиБ исходных текстов в оценке UTF-16, до 64 МиБ новых файлов за один импорт A/B и до 256 МиБ JSON-комплекта при восстановлении. Существующие ограничения движения: 20 эталонов в текущей истории, 40 000 samples на прогон, 120 000 samples в памяти истории. Квота браузера может закончиться раньше. Ошибка показывается явно; доступные данные остаются в памяти и экспортируются, в том числе RAF, которые не удалось дописать на диск. Не закрывайте страницу до экспорта. Прежние эталоны и одиночные форматы читаются прежними импортёрами.

Для автоматического итога нужны отдельно согласованные критерии: допустимое покрытие и неопределённость, приоритет метрик, обработка непригодных пар, достаточное число независимых повторов и аппаратная проверка повторяемости. На этом этапе эти решения не подменяются общим баллом.

## API модулей

`motion-ab.js` доступен как `MotionAB` в браузере и CommonJS в Node. `VERSION` задаёт версию адаптера, `FORMAT` задаёт формат серии. Объекты серии изменяются только функциями управления состоянием; вычисления не меняют входные эталоны и журналы. Ошибочные варианты, ID, связи, версии и контрольные суммы вызывают `Error`.

| Функции | Вход и результат | Изменение состояния |
|---|---|---|
| `create(options)` | Фактор, варианты, число пар и `base_values`; возвращает независимую копию серии | Нет |
| `schedule(series)` | Серия; массив позиций с парой, A/B, порядком и номером | Нет |
| `begin(series, details)`, `select(series, pair, slot, run_id)` | Добавляют попытку или назначают её для сравнения | Переданная серия |
| `sha256(text)`, `canonical(value)` | UTF-8 строка → Promise SHA-256; объект → канонический JSON | Нет |
| `sourceRunIds(data)`, `registerSource(series, source)`, `bind(series, run_id, hash)` | ID из кадров; Promise регистрации `{raw,data,name}`; проверенная привязка источника | Регистрация и привязка меняют серию |
| `recordAnalysis(series, run_id, analysis)` | Результат, `source_hash`, параметры; возвращает сохранённую версию | Переданная серия |
| `metrics(result, journal)`, `latencies(journal)` | Адаптер метрик; задержки с n и долей пригодных публикаций | Нет |
| `delta(A, B)`, `compareKnown(A, B)` | Метрики → консервативная разность; значения → equal/unknown/different | Нет |
| `conditions(series,A,B,analysisA,analysisB)`, `compare(series,pair,runs)`, `summarize(series,runs)` | Проверки условий, таблица пары и сводка | Нет |
| `exportBundle(series,runs)`, `importBundle(bundle)` | Promise полного комплекта; Promise `{series,runs}` после проверки | Нет |
| `csv(series,runs)` | Строка CSV с таблицами всех пар | Нет |

Интервалы метрик используют `lower`/`upper`, точные значения используют `value`; отсутствующие значения имеют `status` и `reason`. Время задано в `ms`, ошибка центра в `camera_px`, доли в `fraction`, разности долей в `pp`. Публичные методы `MotionStore.ab(value?)`, `begin(run,scenario,ab?)` и `end(key,run,ab?)` возвращают Promise по завершении транзакции; отказ квоты или IndexedDB отклоняет Promise. `MotionUI.startAB(context)` запускает прежний контроллер с зафиксированным контекстом, а `MotionABUI` связывает его с сохранённой серией.
