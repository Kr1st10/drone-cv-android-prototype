# Протокол испытания «телефон → 4K-монитор» (этап 6.6)

Цель — понять, при каком **размере объекта в кадре анализа** приложение находит дрон, как ведёт себя на птицах, самолётах и пустом небе, и есть ли разница 1× и 5× на Xiaomi 17T Pro и Xiaomi 17 Pro. Это стендовый тест; дальность до реального дрона из него напрямую не следует.

## 1. Установка

- Монитор 4K (3840×2160), яркость постоянная (например, 80 %), без бликов от ламп/окон. Масштаб браузера 100 %, галерея на весь экран (F), фон чёрный.
- Телефон на штативе, камера по центру экрана, ось камеры перпендикулярна экрану. **Расстояние фиксировано** и записывается в прогон («Расстояние до экрана, см»), например 100 см. Для 5× весь экран в кадр не помещается — это нормально: галерея ставит центр рамки объекта в центр экрана (в быстром тесте снимок при этом в масштабе «вписать», края могут уходить за экран).
- Приложение: режим камеры, порог confidence в приложении не менять между прогонами (по умолчанию ползунок 25 %; в расширенном режиме его можно записать). Кадр анализа — 640×480 (UI показывает `W×H`). Запомнить зум (1× или 5×) и физический ID камеры, показанные в UI.
- Не трогать телефон во время прогона.

## 2. Выборка и прогоны

- **Выборка** — фиксированный список изображений: количество по каждой из шести категорий + seed. Пресет **«Пилот — 20 фото»**: 5/5/3/3/2/2, seed 66020, код `S0d95e824` (одинаков на любом компьютере). Полный набор — «Все 90 фото». Выборка сохраняется в браузере и в «Экспорт JSON» (`sample.ids`).
- **Прогон** — один показ выборки с конкретными телефоном, зумом и расстоянием. Каждый новый прогон («Начать прогон») показывает **те же изображения в том же порядке**; для сравнения 1× и 5× достаточно сменить зум и начать новый прогон. Новую выборку формировать только для новой серии.
- При смене телефона, зума или расстояния — новый прогон (в расширенном режиме с калибровкой — и новая калибровка).

## 3. Быстрый тест (по умолчанию)

Нужны только модель телефона, 1×/5×, расстояние и результат. Снимок в масштабе «вписать в экран», объект — в центре экрана; размер объекта в кадре не задаётся и не спрашивается.

Для каждого снимка:
1. Дождаться стабилизации (≈ 2–3 с, несколько кадров анализа).
2. **R** → выбрать, что видно на экране телефона: **1** — рамка на показанном объекте (дрон, птица, самолёт); **2** — рамка только в другом месте (не на объекте); **3** — рамок нет. Результат сохраняется сразу; форма не показывает категорию.
3. **A** — правильный ответ и итог записи (TP/FN/FP/TN). До сохранения A только напоминает нажать R. Повторное R переписывает результат этого показа.
4. **→** — следующий снимок.

Итог (`result_class`) считается после записи: дроны (`civil_quadcopter`, `military_uav`, `uav_payload`) — 1 → TP, 2/3 → FN; птицы, самолёты, пустое небо — 1/2 → FP, 3 → TN. `false_alarm` — была ли ложная рамка (для дронов — ответ 2 или `fp_count` > 0).

## 4. Расширенный режим

Включается переключателем «Расширенный режим». Все дополнительные поля необязательны; пустое поле сохраняется как `null` («не измерено»), а не как число.

### Калибровка (нужна только для режима «px кадра камеры»)

1. Нажать **C** — квадраты со стороной 512, 256, 128, 64, 32, 16 px монитора (галерея учитывает `devicePixelRatio`).
2. На телефоне сделать скриншот экрана приложения.
3. На скриншоте измерить сторону квадрата 256 px (`a`, px скриншота) и ширину области превью (`P`, px скриншота). Размер в кадре анализа: `s = a / P × W`, где `W` — ширина кадра анализа из UI (640).
4. Ввести `s` → галерея посчитает `k = s / 256` (px кадра камеры на 1 px монитора).
5. Проверка: квадрат 64 px должен дать ≈ `64·k` px кадра.

### Режимы масштаба

- **Объект = N px кадра камеры:** большая сторона объекта в кадре анализа — N px; уровни, например, **16, 32, 64**. Требует `k`.
- **Объект = N px монитора:** без калибровки, для сравнения установок.
- **Фиксированный коэффициент** и **вписать** — для обзора.
- Негативы во всех режимах вписываются в экран (объекта нет). С уровнями N каждое изображение выборки показывается на каждом уровне (блоками по уровню).

### Дополнительные поля записи

`target_conf_pct` (max confidence рамки на объекте), `fp_count`, `fp_max_conf_pct` (рамки не на объекте; на птицах/самолётах любая рамка «drone» — ложная), `object_camera_px_measured` (размер объекта в кадре по скриншоту), заметка. После выбора 1/2/3 сохранить — Enter.

## 5. Размеры и экспорт

| Поле | Единица | Источник |
|---|---|---|
| `object_monitor_px`, `object_monitor_mm` | px / мм монитора | считает галерея: рамка манифеста × масштаб показа × `devicePixelRatio`; мм — только если указана ширина монитора; у негативов `null` |
| `object_camera_px_expected` | px кадра анализа | `object_monitor_px × k`; без калибровки `null` |
| `object_camera_px_measured` | px кадра анализа | измерение оператора; не измерено — `null` |
| `object_yolo_px` | px входа YOLO | (измеренный, иначе ожидаемый) px кадра × min(вход / ширина кадра, вход / высота кадра); источник — `object_yolo_px_source` (`measured` / `calibration`); иначе `null` |

Рамки манифеста приблизительные (агентская разметка), поэтому `object_monitor_px` — оценка размера, а не точное измерение.

- «Экспорт CSV»: одна строка — один показ, столбцы как в `results_template.csv` (`run_id`, `sample_id`, `image_id`, `category`, `phone`, `camera_zoom`, `distance_cm`, `detection`, `result_class`, …); пустая ячейка = `null`.
- «Экспорт JSON» (`dronecv66-session-2`): выборка (`sample.ids`), список прогонов, текущий прогон с порядком, все записи. «Импорт JSON» восстанавливает их.
- Файлы приложить к issue/PR вместе с моделью телефона, версией APK и фото установки.

### Что считать

- Recall по категориям дронов отдельно для 1×/5× (и уровней N в расширенном режиме): сравнивать только прогоны одной выборки (`sample_id`).
- FP: доля показов птиц/самолётов/пустого неба с рамкой; в расширенном режиме — max confidence ложных.
- Сравнение 17T Pro и 17 Pro — только при одинаковой выборке, расстоянии и пороге.

## 6. Интерпретация и оговорки

- `object_monitor_px` / `object_monitor_mm` — размер на экране; `object_camera_px_expected` — ожидаемый размер в кадре по калибровке; это **не** дальность. Перевод в дальность требует реального размера объекта и параметров камеры и проверяется только полевыми испытаниями.
- Экран искажает картинку (муар, гамма, отражения, частота обновления). Сравнивать конфигурации допустимо, абсолютные значения переносить на реальное небо — нет.
- Набор маленький (≈ 90 снимков), доверительные интервалы широкие: на 20 изображениях recall 0.5 имеет 95 % ДИ ≈ 0.3–0.7; в пилоте всего 13 снимков с дронами — это проверка установки и процедуры, а не оценка качества.
