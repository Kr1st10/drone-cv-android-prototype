# Протокол испытания «телефон → 4K-монитор» (этап 6.6)

Цель — понять, при каком **размере объекта в кадре анализа** приложение находит дрон, как ведёт себя на птицах, самолётах и пустом небе, и есть ли разница 1× и 5× на Xiaomi 17T Pro и Xiaomi 17 Pro. Это стендовый тест; дальность до реального дрона из него напрямую не следует.

## 1. Установка

- Монитор 4K (3840×2160), яркость постоянная (например, 80 %), без бликов от ламп/окон. Масштаб браузера 100 %, галерея на весь экран (F), фон чёрный.
- Телефон на штативе, камера по центру экрана, ось камеры перпендикулярна экрану. **Расстояние от камеры до плоскости экрана фиксировано** и измеряется в см. Поле изначально пустое; если не измерено, сохраняется null, угловая ширина и эквивалентная дальность недоступны. Для 5× весь экран в кадр не помещается — это нормально: галерея ставит центр рамки объекта в центр экрана (в быстром тесте снимок при этом в масштабе «вписать», края могут уходить за экран).
- Приложение: режим камеры, порог confidence не менять между прогонами и записать фактическое значение. Камера приложения начинает с 50 %; поле условий галереи первоначально содержит 25 % и не управляет приложением. В быстром режиме поле скрыто, `app_conf_threshold_pct` сохраняется как null: записывайте порог отдельно либо используйте расширенный режим с заполненным полем. Анализ предпочитает 640×480, но итоговый размер выбирает CameraX; запишите `W×H` из UI. Канонические значения — [конфигурация](../../docs/reference/configuration.md). Запомните зум (1× или 5×) и физический ID камеры, показанные в UI.
- Не трогать телефон во время прогона.

## 2. Выборка и прогоны

- **Выборка** — фиксированный список изображений: количество по каждой из шести категорий + seed. Пресет **«Пилот — 20 фото»**: 5/5/3/3/2/2, seed 66020, код `S0d95e824` (одинаков на любом компьютере). Полный набор — «Все 90 фото». Выборка сохраняется в браузере и в «Экспорт JSON» (`sample.ids`).
- **Прогон** — один показ выборки с конкретными телефоном, зумом и расстоянием. Каждый новый прогон («Начать прогон») показывает **те же изображения в том же порядке**; для сравнения 1× и 5× достаточно сменить зум и начать новый прогон. Новую выборку формировать только для новой серии.
- При смене телефона, зума или расстояния — новый прогон (в расширенном режиме с калибровкой — и новая калибровка).

## 3. Быстрый тест (по умолчанию)

Нужны только модель телефона, 1×/5×, расстояние и результат. Снимок в масштабе «вписать в экран», объект — в центре экрана; размер объекта в кадре не задаётся и не спрашивается.

Для каждого снимка:
1. Дождаться стабилизации (≈ 2–3 с, несколько кадров анализа).
2. **R** → выбрать, что видно на экране телефона: **1** — рамка на показанном объекте (дрон, птица, самолёт); **2** — рамка только в другом месте (не на объекте); **3** — рамок нет. Результат сохраняется сразу; форма не показывает категорию.
3. **A** — правильный ответ и итог записи (TP/FN/FP/TN). До сохранения A только напоминает нажать R. Повторное R переписывает результат этого показа.
4. **→** — следующий снимок.

Итог (`result_class`) считается после записи: дроны (`civil_quadcopter`, `military_uav`, `uav_payload`) — 1 → TP, 2/3 → FN; птицы, самолёты, пустое небо — 1/2 → FP, 3 → TN. `false_alarm` — была ли ложная рамка (для дронов — ответ 2 или `fp_count` > 0).

## 4. Расширенный режим

Включается переключателем «Расширенный режим». Все дополнительные поля необязательны; пустое поле сохраняется как `null` («не измерено»), а не как число.

### Калибровка (нужна только для режима «px кадра камеры»)

1. Нажать **C** — квадраты со стороной 512, 256, 128, 64, 32, 16 px монитора (галерея учитывает `devicePixelRatio`).
2. На телефоне сделать скриншот экрана приложения.
3. На скриншоте измерить сторону квадрата 256 px (`a`, px скриншота) и ширину области превью (`P`, px скриншота). Размер в кадре анализа: `s = a / P × W`, где `W` — фактическая ширина upright crop из UI (например, 640 в альбомной ориентации), а не заранее заданный размер сенсора.
4. Ввести `s` → галерея посчитает `k = s / 256` (px кадра камеры на 1 px монитора).
5. Проверка: квадрат 64 px должен дать ≈ `64·k` px кадра.

### Режимы масштаба

- **Объект = N px кадра камеры:** большая сторона объекта в кадре анализа — N px; уровни, например, **16, 32, 64**. Требует `k`.
- **Объект = N px монитора:** без калибровки, для сравнения установок.
- **Фиксированный коэффициент** и **вписать** — для обзора.
- Негативы во всех режимах вписываются в экран (объекта нет). С уровнями N каждое изображение выборки показывается на каждом уровне (блоками по уровню).

### Дополнительные поля записи

`max_confidence_pct` доступно в обоих режимах: необязательное число 0–100 (включая дробные), максимум за время наблюдения. Для 1 — рамка на проверяемом объекте, для 2 — ошибочная рамка в другом месте; для 3 и пустого ввода — null. В быстром режиме вводите до выбора 1/2 (выбор сохраняет сразу). При выбранном варианте 3 поле скрыто; для добавления confidence при повторной записи в быстром режиме сначала сохраните 1/2, затем снова нажмите R. Старые JSON без поля импортируются с null; CSV использует пустую ячейку для null.

`target_conf_pct` (max confidence рамки на объекте), `fp_count`, `fp_max_conf_pct` (рамки не на объекте; на птицах/самолётах любая рамка «drone» — ложная), `object_camera_px_measured` (размер объекта в кадре по скриншоту), заметка. После выбора 1/2/3 сохранить — Enter.

Форма R в расширенном режиме также содержит ширину коптера, источник габарита и измеренную ширину изображения на мониторе. Значения относятся только к текущему показу: при повторном R восстанавливаются, на другой снимок или уровень не переносятся. Это исключает перенос габарита одной модели на другую. Поля размеров принимают только положительные числа или пустое значение.

### Короткий эксперимент для 10-дюймового коптера: 1× и 5×

1. Выберите снимок **известной модели** в выборке. 10″ означает диаметр пропеллеров: не вводите 25,4 см как ширину аппарата. Возьмите полный габарит из характеристик именно этой комплектации или измерьте аппарат. В поле «Модель, источник габарита и границы ширины» запишите модель, ссылку/описание замера и точки A–B. Ракурс должен показывать эту ширину без существенного перспективного сокращения. Наличие подходящего 10″ коптера среди 90 фото не подтверждено: для неизвестных моделей оставьте габарит пустым; их обнаружения можно учитывать, но дальность именно 10″ аппарата они не доказывают. При необходимости подходящий снимок сначала нужно включить в манифест отдельной подготовкой данных.
2. Зафиксируйте монитор 3840×2160, fullscreen, масштаб браузера 100 %, фон, яркость, освещение, положение/ориентацию телефона. Измерьте расстояние **от камеры** до экрана. Запишите телефон, APK, физический ID камеры, параметры фокуса/экспозиции, размер анализа W×H и условия в заметке первой записи/сопроводительном журнале. После каждой смены зума проверяйте фактическую камеру и кадр анализа.
3. В приложении установите **50 % confidence** и не меняйте в серии; в расширенном режиме галереи введите фактические 50 %. Это условие эксперимента, не автоматическое управление приложением. Если используется иной порог, заранее запишите его и проведите отдельную серию.
4. Сохраните выборку с seed, включающую проверяемый коптер и контрольные птицы/самолёты/пустой фон. Для **1×** выполните существующую калибровку C, проверьте её по второму квадрату. Выберите «объект = N px кадра камеры», например уровни **64,32,16,8**. Начните прогон. N — большая сторона рамки; не переименовывайте её в физическую ширину A–B.
5. Для каждого показа до открытия R измерьте линейкой на экране расстояние между **теми же A–B** в мм. На скриншоте оцените большую сторону объекта в px кадра анализа по геометрии превью (как при калибровке); вводите её в уже существующее поле размера, а при отсутствии замера используйте оценку k. Полностью обрезанные экраном/камерой объекты исключайте из серии и поясняйте причину; не подставляйте их частичную ширину.
6. После стабилизации наблюдайте **10 секунд** на каждом показе (одинаково для всех уровней). Запишите 1/2/3 и максимальный confidence за это окно, а также физические размеры и источник. В этой серии «обнаружение» означает хотя бы одну рамку на объекте за окно при фиксированном пороге; это не доля кадров с детекцией. Чтобы не считать редкий всплеск устойчивым обнаружением, дополнительно опишите устойчивость рамки в заметке; галерея не измеряет её автоматически.
7. Для **5×** оставьте телефон на той же отметке, выберите зум в приложении и галерее, заново измерьте k и W×H. Новый прогон использует ту же выборку, порядок и уровни N. Изображение на мониторе при этом может быть меньше: **повторно измерьте мм**. Геометрическую дальность не нужно дополнительно умножать на 5.
8. Повторите каждый режим **трижды** новыми прогонами (R на прежнем показе заменяет запись, не создаёт повтор). Экспортируйте CSV/JSON после каждого прогона. В S смотрите TP/проверок по размерам и отдельные FP/негативов. Сравнивайте 1× и 5× при одинаковом пороге, расстоянии, выборке и окне наблюдения. Заранее задайте критерий приемлемой доли (например, ≥90 % окон в каждом из трёх повторов); отчёт должен содержать и числитель/знаменатель. Стенд показывает переход доли обнаружений, а реальная полевая дальность требует отдельного испытания.

## 5. Размеры и экспорт

| Поле | Единица | Источник |
|---|---|---|
| `object_monitor_px`, `object_monitor_mm` | px / мм монитора | считает галерея: рамка манифеста × масштаб показа × `devicePixelRatio`; мм — только если указана ширина монитора; у негативов `null` |
| `object_camera_px_expected` | px кадра анализа | `object_monitor_px × k`; без калибровки `null` |
| `object_camera_px_measured` | px кадра анализа | измерение оператора; не измерено — `null` |
| `object_yolo_px` | px входа YOLO | (измеренный, иначе ожидаемый) px кадра × min(вход / ширина кадра, вход / высота кадра); источник — `object_yolo_px_source` (`measured` / `calibration`); иначе `null` |
| `distance_cm` | см | измерение от камеры смартфона до плоскости монитора; пустое — `null` |
| `drone_width_cm` | см | физическая ширина выбранного аппарата A–B по характеристикам/замеру; без подтверждения — `null` |
| `drone_width_source` | строка | модель, ссылка на характеристики или описание собственного замера, границы A–B; пустое — `""` |
| `screen_object_width_mm` | мм | замер линейкой между теми же A–B на изображении при данном масштабе; пустое — `null` |
| `object_angular_width_deg` | градусы | `2 × atan(screen_object_width_mm / (20 × distance_cm)) × 180 / π`; без обоих положительных размеров — `null` |
| `equivalent_distance_m` | м | геометрическая эквивалентная дальность (формула ниже); для негативных категорий и неизвестных размеров — `null` |

Рамки манифеста приблизительные (агентская разметка), поэтому `object_monitor_px` — оценка размера, а не точное измерение.

Существующие размеры `object_*_px` и `object_monitor_mm` относятся к **большей стороне рамки**. Новые физические поля относятся к выбранной **ширине A–B**. Поэтому `object_monitor_mm` не подставляется в формулу вместо измеренного `screen_object_width_mm`.

```text
screen_object_width_cm = screen_object_width_mm / 10
D_equiv_m = drone_width_cm * distance_cm / screen_object_width_cm / 100
```

Все физические размеры в отношении ширин должны описывать один габарит A–B. Например, **тестовые**, не измеренные на стенде числа: 60 см × 150 см / (60 мм / 10) / 100 = **15 м**. Неизвестное/неположительное/нечисловое измерение даёт `null`. В UI неположительный ввод отклоняется. Геометрия предполагает центрированный объект и перпендикулярную установку; зум в формулу не входит.

- «Экспорт CSV»: одна строка — один показ, столбцы как в `results_template.csv` (`run_id`, `sample_id`, `image_id`, `category`, `phone`, `camera_zoom`, `distance_cm`, `detection`, `result_class`, …); пустая ячейка = `null`.
- «Экспорт JSON» (`dronecv66-session-2`): выборка (`sample.ids`), настройки, список прогонов, текущий прогон с порядком, все записи и вычисляемая `size_summary`. Старый формат и ключи браузера сохранены. Для прежних записей новые числовые поля становятся null, источник — пустой строкой; импорт не требует новых полей. Расчётные угол/дальность пересчитываются из исходных измерений, `size_summary` при импорте не применяется, а строится заново. Импорт восстанавливает подходящую выборку и текущий прогон, добавляет отсутствующие runs/results; для результатов требуется подтверждение. Уже существующие ключи не перезаписываются, корневые settings не применяются — проверьте настройки вручную перед новым прогоном.
- Файлы приложить к issue/PR вместе с моделью телефона, версией APK и фото установки.

### Технический формат JSON

Источник формата — `sessionJson()`/`saveRecord()`/обработчик `importJson` в [gallery.html](gallery.html).
JSON не содержит изображения. Даты `created`, `exported`, `recorded_at` имеют формат ISO 8601 UTC (`Z`).

| Объект | Поля и типы |
|---|---|
| Корень | `format: string` (`dronecv66-session-2`), `exported: string`, `manifest_version: string`, `manifest_sha256: string/null`, `sample: object/null`, `runs: array`, `trial: object/null`, `settings: object/null`, `results: array`, `size_summary: array` |
| `sample` | `sample_id,name: string`, `seed: number`, `counts: object` (category → integer), `ids: array<string>` в порядке показа, `created,manifest_version: string` |
| `runs[]` | `run_id,created,sample_id,sample_name,phone,zoom,mode: string`, `distance_cm: number/null`, `shows: integer` |
| `trial` | `run_id,created,manifest_version,sample_id,sample_name: string`, `manifest_sha256: string/null`, `sample_seed: number`, `sample_ids: array<string>`, `settings: object`, `order: array<{id: string, level: number/null}>`, `index: integer` (с 0) |
| `settings` / `trial.settings` | `mode: quick/advanced`, `scaleMode: fit/native/monitor/camera`, `scaleFactor: number`, `sizes: array<number>`, `center: boolean`, `bg: string`, `phone,zoom,operator: string`; `distance_cm,app_conf_pct,monitor_mm,monitor_px,k,frame_w,frame_h,yolo_input: number/null`. Корневые и advanced trial.settings также содержат `seed: number`; quick trial.settings не содержит seed |
| `results[]` | Поля совпадают с 41 столбцом [CSV](results_template.csv). Идентификаторы/имена/phone/zoom/mode/enum/дата/заметка/`drone_width_source` — строки, `step` — integer с 0, `sample_seed` — number, `false_alarm` — boolean, размеры/угол/дальность/confidence/счётчики — number/null |
| `size_summary[]` | `run_id,camera_zoom,kind,camera_px_source: string`, `camera_px: number/null`, `checks,correct_detections,false_positives,distance_known_count: integer`, `detection_rate,false_positive_rate,equivalent_distance_min_m,equivalent_distance_max_m: number/null` |

`detection` в JSON/CSV: `box_on_object` (ответ 1), `box_elsewhere` (2), `no_box` (3).
`result_class`: `TP`, `FN`, `FP`, `TN`. `camera_zoom`/`runs[].zoom`: строки `1x`/`5x`;
`test_mode`/mode: `quick`/`advanced`; `scale_mode`/scaleMode: `fit`/`native`/`monitor`/`camera`.
`size_level_unit` — `monitor_px`/`camera_px`/null; `object_yolo_px_source` — `measured`/`calibration`/null.
В quick trial.settings принудительно использует fit, пустые sizes, center=true и null для неизмеряемых полей,
в том числе порога; корневые settings могут содержать другие значения скрытых полей.

Импорт не является полной схемной валидацией: проверяет format и известные sample.ids, принимает trial,
объединяет runs по `run_id`, результаты по `(run_id, step)` без замены уже существующих ключей.
Корневые settings, exported и manifest metadata сами настройки браузера не меняют. Используйте собственные
экспорты совместимого формата и проверьте параметры перед продолжением/новым прогоном.

### Что считать

- В настройках S есть сводка по размерам кадра анализа; та же сводка — в JSON `size_summary`. Каждая группа ограничена одним `run_id`, типом `drone`/`negative` и источником размера; прогоны с разными условиями не смешиваются. Измеренные px имеют приоритет над калибровкой; размер округляется до 0,1 px, без данных — отдельная группа `unknown`. Размеры 15,9 и 16,1 px остаются разными группами, заранее заданные интервалы не применяются.
- Для дронов: `checks`, `correct_detections` (TP), `detection_rate = TP/checks`; диапазон эквивалентной дальности min…max и `distance_known_count` только по записям с известными измерениями (включая пропуски). Группа не удостоверяет, что все её аппараты 10″: это надо проверить по источникам габаритов.
- Для негативов (птицы, самолёты, пустой фон): `checks`, `false_positives` (число показов с `false_alarm`), `false_positive_rate`; доля TP и дальность — null. У пустого фона нет размера объекта, поэтому в режиме camera `camera_px_source=control_level` означает **лишь номер контрольного блока N**, не измеренный размер; без camera-уровня — `unknown`. Для измеренных/калиброванных объектов источники — `measured`/`calibration`.
- Recall по категориям дронов отдельно для 1×/5× (и уровней N в расширенном режиме): сравнивать только прогоны одной выборки (`sample_id`).
- FP: доля показов птиц/самолётов/пустого неба с рамкой; в расширенном режиме — max confidence ложных.
- Сравнение 17T Pro и 17 Pro — только при одинаковой выборке, расстоянии и пороге.

## 6. Интерпретация и оговорки

- `equivalent_distance_m` — расстояние до реального объекта указанной ширины с таким же угловым размером, как у измеренного изображения на мониторе. Это **не доказанная реальная дальность обнаружения**. Параметры камеры не нужны для этой геометрической формулы, но калибровка нужна для связи с пикселями кадра; перенос обнаружений в реальную сцену требует полевого испытания.
- Экран искажает картинку (муар, гамма, отражения, частота обновления). Сравнивать конфигурации допустимо, абсолютные значения переносить на реальное небо — нет.
- Набор маленький (≈ 90 снимков), доверительные интервалы широкие: на 20 изображениях recall 0.5 имеет 95 % ДИ ≈ 0.3–0.7; в пилоте всего 13 снимков с дронами — это проверка установки и процедуры, а не оценка качества.
